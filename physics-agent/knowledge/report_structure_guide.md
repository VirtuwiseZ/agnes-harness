# 物理研究报告行文结构指南（从竞赛范文提炼，方法论层面，非答案）

本文档收纳从 `dev-notes/reference-solutions/` 目录下已知竞赛范文（2010-GM-B-210、
2020-GM-A-340、2023-GM-A-131）里提炼出来的**行文逻辑结构**，供 Node 3 撰写
报告时参考。提炼的是"这类报告应该怎么组织"的方法论，**不是**任何一道具体
题目的答案、公式或数值——具体数值和公式始终来自本题自己的 pipeline 运行
结果（Node 2b 的 `numerical_artifacts`），本文档只提供章节组织顺序。

## 从三份范文共同提炼出的标准章节顺序

| 顺序 | 章节 | 内容要求 | 对应 Node 3 增量写作时机 |
|---|---|---|---|
| 1 | 摘要 | 问题一句话概括 + 方法论一句话 + 关键数值结论（含单位）+ **核心物理规律提炼**（提炼该系统的主导物理机制与定性变化趋势，而不只是孤立数字）。**先给答案，不先给过程**，跟正文顺序相反 | Node 2b 完成后（Node 3 最终整合时写） |
| 2 | 引言 / 背景 | 这个问题的物理背景是什么、为什么有意思；并用引用块（`> ...`）完整呈现题干原始表述（直接用自然语言引入，如“题干原始表述如下：”，**严禁**写“题目（原样引用）：”之类带元注释括号的导语） | Node 1 写完后追加 |
| 3 | 假设 | 直接按编号列出所有简化假设（`- **假设 1（名称）**：……`），**不要**散落在正文里，也**严禁**在列表前加“逐条列出（正文里用编号引用，不再临时引入新假设）：”这类复述写作规则的元导语 | Node 1 完成后追加 |
| 4 | 建模（主推导） | 按物理阶段/子问题分段，每段开头先写"这一段要解决什么问题"，再写推导，最后写"本段结论"；从最简基线模型（Baseline）出发，逐层交代修正项的物理依据 | Node 2a/2b 每完成一个机制段追加 |
| 5 | 验证 | 用独立数据源或独立方法（非同一模型自洽）验证模型预测，**在报告最终结果之前**完成。必须用面向读者的自然语言写明"验证数据/方法来自哪里、跟模型预测差多少"，**严禁**把内部字段名（如 `data_source_decision`、`independent_of = true`）写进报告正文 | Node 2b 完成后追加 |
| 6 | 结果 | 最终答案，带单位、误差范围（若有）；多工况对比或参数扫描表格/图放在这里；**提炼响应曲线演化规律与一阶灵敏度速算规则**（如适用） | Node 2b 完成后追加 |
| 7 | 优缺点 | 显式自我评价：这套方法做对了什么、在哪里做了简化会引入什么误差（直接用中文小标题如“模型优势”“简化与局限”，理论推导题可使用“理论假设与适用局限”）；**明确界定模型的适用范围（Regimes of Validity）与失效边界（Breakdown Boundaries）**，不要把局限性藏在脚注里 | Node 3 最终整合时写 |
| 8 | 讨论 / 未来方向 | 什么条件会改变结论（比如"若空气阻力不可忽略，答案会向哪个方向偏移"）；哪些假设若放宽会显著改变结果；**探讨反直觉物理规律、渐近极限退化、临界相变阈值与更广阔的应用场景**（参考 `physics_research_methodology.md`） | Node 3 最终整合时写 |

## 复合多问型与大学物理教学推导题目的八章组织范式（泛用性指南）

当面临大学物理课内推导、教学阐释或包含多个连续递进子问题的题目（例如“①白光单缝衍射光强分布、②光学仪器分辨本领推导、③航天员太空看长城定量分析、④显微镜最高分辨率为何”）时，**绝不需要分裂为多份独立报告**，而是在标准八章结构中以清晰的二级小节逻辑递进展开：

1. **第 1 章 摘要**：结论先行，集中陈述全部子问题的核心结论与量化指标（如白光中央白两侧彩条特征、仪器角分辨率公式、航天员在 300km 处极限分辨率约 67m 对比长城宽度 5~8m 从而肉眼无法分辨、显微镜最高分辨率 $\sim 0.2\,\mu\text{m}$）；
2. **第 2 章 引言与背景**：阐述现象背后的物理内核（如波动光学中光波波长对宏观遥感与微观成像所设立的物理衍射极限）；
3. **第 3 章 假设**：集中列出全部物理近似（如傍轴小角近似、人眼明视觉瞳孔公称直径 $D=3\,\text{mm}$、可见光中心波长 $\lambda=550\,\text{nm}$、显微物镜典型数值孔径 $\text{NA}=1.4$ 等）；
4. **第 4 章 建模（主推导）**：按子问题顺序划分子节（如 4.1 单缝衍射积分与多波长 RGB 光强空间分布、4.2 圆孔衍射艾里斑与瑞利分辨判据、4.3 航天器轨道高度地面线分辨率函数与长城辨识、4.4 显微物镜孔径角正弦条件与阿贝极限），每节给出清晰推导与代数闭合解；
5. **第 5 章 验证**：采用理论物理的独立验证范式（如 $\lambda \to 0$ 几何光学直线投影退化极限、解析解与波面面元数值积分残差比对、瑞利判据与道威斯/斯帕罗判据交叉对比）；
6. **第 6 章 结果**：分别汇总各子问题的数值表格、光强分布曲线族、彩色条纹仿真图与高度-分辨率关系曲线；
7. **第 7 章 优缺点（理论假设与适用局限）**：针对理论推导题，小标题可定为“模型优势”与“理论假设与适用局限”（如傍轴近似的角域限制、单色有效波长代替连续光谱的简化误差、未计入真实大气湍流调制传递函数 MTF 的理想化假设等）；
8. **第 8 章 讨论与未来方向**：探讨前沿延伸（如超分辨率 STED 技术对阿贝极限的突破、空间自适应光学与合成孔径雷达在破除光学衍射极限中的应用）。


## 行文风格层面的七条约束（Node 3 写作与 Node 4 交付前必检）

1. **"结论先行"原则**：摘要和每个小节的开头都要先给"这个部分得出了什么"，
   再给"怎么推导的"。读者不应该需要读完整个推导段落才知道这段在说什么。
2. **"假设显式化"原则**：所有简化假设必须集中放在"假设"章节并按编号列出，
   正文里引用假设时直接写编号（如"由假设 3 可知"），不在正文里临时引入未编号的新假设。
3. **"验证独立于建模"原则**：验证章节的数据源或校验方法必须跟建模章节不同，
   验证失败时要写明"失败在哪一步、差了多少、是否可接受"，不能只写"验证通过"。
4. **公式必须用 LaTeX 定界符（`$...$` 行内、`$$...$$` 行间），不使用 Unicode
   上下标字符（如 `x₁`、`α`、`≤`）冒充公式排版**：行内公式一律写成
   `$v = gt$`，独立成行的公式用 `$$...$$` 包起来；下标用 LaTeX 语法
   （`x_0`），不要用 Unicode 下标字符（`x₀`）直接写进正文冒充排版。
5. **数据表格必须用真实 markdown 管道语法（`|` 分隔的表格行 + 表头下方一行
   分表线），不允许把表格数据写成普通文本行（逗号/空格分隔、没有 `|`）冒充
   表格**：一张表 = 一行表头（每个单元格用 `|` 分隔）+ 一行表头分隔线
   （`|---|---|`，列数跟表头一致）+ 若干行数据行（同样用 `|` 分隔），
   跟文档开头"标准章节顺序"那张表用的是同一种语法。
6. **各级标题（`#`/`##`/`###`）纯粹表达物理与逻辑主题，不带任何元注释或自我评价式括号**：
   标题里严禁写"（本轮说明）""（注：……）""（此处省略）""（先给结论）"这类元叙述；
   报告开头与结尾也**一律不得**附加诸如"本轮执行说明""报告组织说明"等解释写作过程或流水线节点的段落。
7. **严禁正文行内元导语、自我标榜及内部协议字段透传（B1 + E5 铁律）**：
   报告的目标读者是物理研究的使用者，而非本项目的开发者。正文中**绝对禁止**出现指涉"AI 如何遵守了某条写作规则"的行内括注、向开发者表功的自我标榜段落，或任何内部 JSON 字段名 / 流水线节点名。

### 第 7 条典型反例与正例改写对照表（写作后必须逐项自检）

| 违规类型 | 严禁出现的反例（全部取自真实翻车案例） | 正确的科研报告写法（正例） |
|---|---|---|
| 复述引用规则的元括注 | `题目（原样引用）：` | `题干原始表述如下：`（随后直接接 `>` 引用块） |
| 复述假设规则的元导语 | `逐条列出（正文里用编号引用，不再临时引入新假设）：` | 直接开始列 `- **假设 1（双体弹性近似）**：……`（无需任何元导语） |
| 透传内部 JSON 字段名 | `**独立于建模数据源的交叉验证**（与 data_source_decision.verification_baseline.independent_of = true 一致）：` | `**独立交叉验证**：采用不依赖卫星星历表的齐奥尔科夫斯基公式与解析几何上界进行独立核验：` |
| 透传流水线黑话与自我标榜 | `### 本轮执行说明：本报告是 governance 6 节点 pipeline 的正式产物（§0 状态检查、§1 三道防线、Node 2b numerical_artifacts、internal_prior_divergence_check……）` | **整段彻底删除**（物理研究报告只呈现物理问题、方法、数据与结论，绝不汇报 AI 内部走过了哪几个 Node 或写了哪个 JSON 字段） |

### 确定性 Lint 黑名单（由 `report_quality_check.py` 自动拦截）

报告 Markdown 与最终生成的 HTML 正文一旦命中以下任一模式，即判定为**未通过交付前自检**，必须改写并重新生成后方可交付：
- 元导语/自我说明类：`（原样引用）`、`不再临时引入新假设`、`正文里用编号引用`、`本轮执行说明`、`本报告是.*正式产物`、`集中放在报告开头`
- 内部协议/字段黑话类：`problem_state\.json`、`data_source_decision`、`independent_of`、`numerical_artifacts`、`internal_prior`、`audit_logs`、`Node\s*[0-4]`、`Level\s*[0-2]`、`governance\s*6\s*节点`、`张冠李戴`

## 边界说明

本文档**不是** §5（参考解答隔离规则）的豁免：它只提供"报告章节应该按什么
顺序组织"的方法论框架，不提供任何一道具体题目应该得出什么数值、什么公式。
Node 3 撰写报告时，具体填进上述各章节的内容，始终来自本题自己的 pipeline
运行结果（`numerical_artifacts`、`verification` 字段），不是来自
`dev-notes/reference-solutions/` 里任何一份范文的具体内容。
