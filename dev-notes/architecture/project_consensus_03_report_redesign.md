# 项目开发设计共识备忘录

## 第 3 轮测试（03）之后的共识更新：报告呈现层重设，溯源设计让位于"可验证感"

背景：第 3 轮测试用两道全新题目（2025A Sasando 音板 / 2025B 火炮弹道，见
`dev-notes/self-tests/03/` 及 `ability-test3` 分支）分别做了"审批全通"与
"审批故意出问题"两种场景。协议层（量纲门、边界门、数据源路由、机制匹配、
内部先验、session_key 自动记录、trace 自动抓取）的执行本身都验证通过了，
问题集中出现在**最终报告（Node 3/Node 4 产物）的呈现层**：

### 已定共识（本轮测试后确认，优先级最高）

1. **`artifact_id` 哈希码不再作为面向用户的呈现手段，该设计搁置、可能整体放弃。**
   现状：报告正文与 HTML 的"核验附证"交叉表里，把 64 位哈希码当成"结论可溯源"
   的核心展示（如 `f6518860...` / ⚠ / seq 号）。实测体验（用户原话记录于
   `test3-2审批部分出问题.md` ⑤⑥）：哈希码"乱乱的，只能看不方便查，并不能
   让人感觉很靠谱"；"核验附证"那两列（⚠/seq）对真实用户（提出物理问题的非
   程序员）既看不懂、也无法实际去"点进去看 AGH 运行记录"（此前已验证过：
   从 HTML 里的哈希/seq 点击跳转到对应 AGH 运行记录这一步并没有被实现过，
   只有 seq 数字本身，没有可点击的跳转目标）。
   **决定**：在实现"点击某步 → 跳转到该步实际代码/调用过程/AGH 运行记录"之前，
   不继续投入打磨这套哈希交叉表；`cross_check()` 里哈希子串匹配本身那个已知
   缺陷（"全 ⚠/全 ✅ 都不代表真的语义绑定"）也不再单独立项修复——先搁置，
   等新的呈现方案定下来后一起重新考虑要不要保留/重写。

2. **报告要传递的核心印象，是"这些分析不只是 LLM 编的，而是真的跑过
   Python 程序、且这些程序能点开看代码和调用过程"，而不是"看一堆哈希码"。**
   目标体验：用户在报告里看到某一步（如"量纲校验"）时，能**点开一个可
   查看的片段**——该步实际调用的钩子脚本名（`dimensional_gate.py`）、
   实际跑的命令行/参数、跑出的原始输出（PASS/FAIL 原文）、以及该步的
   物理含义（"这条方程三个加项维度全部一致，所以通过"）——让"确定性
   程序核验过"这件事**看得见摸得着**，而不是只看到一串看不懂的 64 位
   哈希和 ⚠/✅ 图标。哈希/artifact_id 如果未来还要保留，只能作为**藏在
   展开层里、给开发者用的内部字段**，绝不作为正文/折叠面板给用户看的
   第一呈现方式。

3. **报告里"结论 ↔ 运行步骤对应关系"的反复强调，主次颠倒，要调整。**
   现状：报告正文（`report_*.md`）和 HTML 都在大量篇幅里强调"这个结论锚定
   到哪个 artifact / 哪次 tool call"，但对应的查看路径（点开看实际运行
   记录）并不真正可用，造成"反复说可以核验、但核验本身很难操作"的观感
   （用户原话："给我一种主次不分的观感"）。**决定**：正文里"这一步是怎么
   验证的"应该用人话直接说清楚（跑了哪个脚本、输入是什么、得到什么
   结论），把"点击展开看原始调用"作为**可选的、次要的、深藏一层的**
   附加信息，而不是让"对应到哪个 artifact_id"这种表述成为正文的默认
   语气。

4. **报告中出现"AI 自言自语"式措辞，属于呈现层 bug，要修。**
   `test3-1审批全部通过.md` ③：报告里出现"这一点必须在最终结论里明确写出，
   不能藏在代码里"这类明显是 agent 给自己写笔记、不是给用户看的句子，
   被原样带进了面向用户的报告。**决定**：Node 3 生成报告草稿时，要有一道
   明确规则——"写给 agent 自己的后续提醒/待办类句子，不能直接写进
   `report_<slug>.md` 正文；如果确实要留给后续步骤看，应该写进
   `problem_state.json` 的某个内部字段或单独的笔记文件，而不是报告正文"。

5. **报告语言要跟提问语言一致（中文提问就该出中文报告），SKILL.md 里要
   写死，不能靠 agent 自由发挥。**
   `test3-1` ①（补充想法 2）：审批中断后的临时说明、最终报告，都用了英文，
   但用户是中文提问。`developer_feedback_2025B_artillery.md` 的 F3 也独立
   指出了这一点（SKILL.md 现在只有一句很弱的"in the user's language"）。
   **决定**：SKILL.md Node 3 明确"报告正文语言 = 用户对 agent 提问所用
   语言"，中断/收尾说明同样适用。

6. **报告/产物要能"一键打开"，不用进文件管理器逐层翻。**
   `test3-1` ⑤（补充想法 1）：如果 AGH 前端确实做不了会话内可点击链接，
   至少让 agent 用代码块输出一个 `file:///E:/...` 浏览器可直接粘贴打开的
   链接；产物目录最好也放浅一点（比如工作区根下 `reports/<slug>.html`），
   而不是 `program-design/runtime/` 这种 4 级深处。

7. **`program-design/runtime/` 下多个会话的产物目前混在同一目录里，
   要改成按会话/任务分子目录存放。**
   `test3-1` ②：两个不同会话（2025A、2025B）的 `problem_state_*.json`、
   `report_*.md`、各自写的模型 `.py`、trace 抓取输出全部平铺在同一目录，
   已经实际造成了"2025A 的报告里提了 2025B"这类跨任务串档现象
   （`test3-1` ①）。**决定**：Node 1 创建任务专属文件时，路径规范改为
   `program-design/runtime/<task-slug>/`，一个任务一个子目录，天然隔离
   不同会话/任务的资产。

8. **`SKILL.md` / `program-design/` 是否会被运行中的 agent 自己改，目前
   没有证据显示发生过，但要做成可核验的常识，不能只是"看着没问题"。**
   `test3-1` ⑥的疑问（"agent 会不会在运行中自己修改 SKILL.md 或
   program-design 文件"）经核对 `ability-test3` 分支这条 commit 的实际改动
   清单，只新增了任务专属文件（各题的参数 JSON、各题自己写的模型
   `.py`、各题的 `problem_state`/`report`/`trace_capture` 输出），没有
   对既有 `SKILL.md` 或既有钩子脚本产生 diff，**没有证据表明发生过违规
   自改**；但为了让以后每次走查都能快速自查这一点，加一条固定收尾动作：
   每次走查结束后，跑一次"git diff 是否碰到 `program-design/hooks/*.py` /
   `SKILL.md` / 既有模板文件"的检查，作为常规质检步骤，而不是等出事了
   再回头查。

9. **图表/仿真数据的可视化呈现，是"要认真做"的方向，但不是现在做。**
   用户明确：报告里缺乏图表（只有文字+简单表格）是一个真实短板，"仿真
   数据图表绘制功能需要认真做，以提高报告的可读性"，但**这一条先记下，
   不作为下一步立即动手的任务**——先把本轮测试的"流程质量"分析做完、
   上面 1–8 条共识落地后，再单独立项做。

10. **第三轮测试（03）本身的质量分析，按"AGH 与 AI 运行流程细节"而非
    "物理分析对不对"来评。** 用户明确：AI 科学分析合理性这一层，等
    用户提供本次两道题的范文后再结合范文单独评估；当前要先做的是
    "AGH 运行机制 + AI 按协议执行流程"层面的顺利点/不足点，并据此
    提出改进。

### 本轮（第 3 次走查）流程层面的初步观察，供后续逐条落实时参考

- 顺利点：`session_key`/`internal_prior`/`mechanism_match_check` 三个新增
  协议机制，两道题都真实执行了、不是走过场；量纲门在 2025A 上真的拦截到
  一次单位错误（模态方程右端力/面压强混淆）并被当场修正，不是"门根本没
  跑通"的老问题；`trace_capture.cjs` 在 2025B 上实际抓到了完整 trace
  （112 条 tool call），自动抓取这条路本身是通的。
- 待逐条确认/细化的流程细节（本轮先记下，不展开修）：审批"故意出问题"
  场景下，agent 对 §4/§4a 两类停止规则的触发时机、以及"审批被拒/超时"
  之后到底是不是真的按协议停下而不是绕过，需要结合 `test3-2审批部分
  出问题.md` 里描述的完整审批时间线逐条对一遍（用户描述里已经观察到
  "有多次 edit 自动被成功执行但没有事先弹出审批窗口"这类现象，是否属于
  AGH 宿主层面的行为、还是 agent 自己的行为，需要单独核实，先记下不
  下结论）。
