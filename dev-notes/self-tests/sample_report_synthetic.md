# 研究汇报：高空跳伞垂直下降（Space Diving Descent）

## 一、题目拆解与安全边界

本题要求：一名跳伞者（含太空服与降落伞总质量 190 kg）被火箭垂直送至大气层外（或许
高于大气层），然后带伞返回地球表面。要求分析下降过程中的挑战与危险，并求出**能够
安全抵达地面的最大初始高度**。

我从题目中提取的定量目标与安全约束：
- 目标量：最大安全下降初始高度（km），以及该高度下决定安全边界的主导速度/减速度曲线。
- 安全判据（来自题域参数文件 `space_diving_params.json#safety_constraints`）：
  持续 ≤5 g 且持续时间 ≤5 s；峰值 ≤10 g 且持续时间 ≤0.1 s。

本步依据：`problem_state.json → task` 字段（trace seq 对应第一次 `write` 调用）。

## 二、模型假设（Node 2a 方法论适配判断）

我匹配到的方法论模板是 `program-design/knowledge/atmosphere-drag-ode.md`（垂直
下降 ODE，按局地马赫数分段 CD）。

**关键适配判断（不是照搬模板数值）**：模板自带的 CD 分段阈值（Mach 0.8 / 1.2）
与面积参数（A=0.18/0.2 m²）是**模板通用候选值**，不是针对本题（马赫数高达 15 级
的进场条件）重新推导的。我在建模前明确把它标记为"假设"，而不是当作已验证事实：

- 亚音速 CD = 1.0（假设，待数值敏感性检验）
- 跨音速 CD = 5.0（假设，模板候选值，未针对本题音速带重新推导）
- 音速带边界依赖局地音速 a_sound(z)：100–150 km 高度区间约 305–320 K，
  a ≈ 348–358 m/s——这个数值我留到 Node 2b 数值阶段再量化，现在只记为假设。
- 拖曳力在 Mach ≫ 2 时忽略（自由分子区，超出本模型范围），这是明确的模型边界，
  不是数值结果。

以上假设已写入 `problem_state.json → hypothesis_layer.assumptions`，每一条都标了
"待复核"或"模型边界"字样，不是静默采用的。

## 三、数据源判断（Node 1.5，逐级降级）

本题需要外部数据：大气密度/温度随高度分布（模型输入）+ 一份**独立**的经验基准
（验证用，不能和模型输入同源）。

我按四级可靠性排序依次尝试：
- Level 0（本地已装 Python 包）：尝试 `import ambiance` 读一次本地封装好的大气表——
  **被拒**（shell 权限未放开）。
- Level 1（live API）：尝试 3 个在线公开数据源（Wikipedia 大气密度表 / 某个在线
  大气计算器 / 大学课程页）——**全部失败**（网络被沙箱拦截，`WEB_BLOCKED_URL`）。
- Level 3（解析近似）：改用 **US Standard Atmosphere 1976** 的解析近似（有效到
  ~85 km 的常规大气部分；本题要求的 100–150 km 高度区间超出该标准的适用范围，
  这是一个明确的**数据源-模型边界不匹配**，我没有假装它覆盖了整个问题区间）。

数据源选型已写入 `problem_state.json → data_source_decision`，并明确记录了
"独立基准"这一档当前**未落实**（Level 1 全部失败后没有可用的独立数据源，
verification 部分只能先留空，等下次有网络/有权限的环境重跑）。

## 四、数值模型与门禁（Node 2b）

我用 `program-design/hooks/ode_model.py`（数据源无关的 ODE 求解脚本）做垂直下降
积分：状态变量取 u = v²/2（比动能），自变量取下落距离 x，方程为
du/dx = g_eff(z) − [ρ(z)·CD(Mach)·A(Mach)/(2m)]·u，z = z0 − x。

量纲门禁（`dimensional_gate.py`，Pint 引擎）：**通过**。g_eff 项（m/s²）与
阻力项（ρ[kg/m³]·CD[无量纲]·A[m²]/(2m[kg])·u[m²/s²] = m/s²）量纲一致。

边界门禁（`boundary_gate.py`）：h→0（无高度变化）时 du/dx→g，符合自由落体极限；
ρ→0（真空）时阻力项消失，也符合。两条边界都通过。

**但这次运行没能真正跑完数值积分**：`ode_model.py` 需要 shell 权限启动 Python 子
进程，而本会话 shell 权限被拒（见上文第三节、以及 trace 里对应的那几条被拒的
approval 记录）。我**没有**手算替代数值结果、也没有把"未完成的积分"四舍五入成
一个具体的"最大高度"数字——这是协议 §4 明确禁止的（手算替代 ≠ 门禁真正跑过）。

数值结果字段（`problem_state.json → numerical_artifacts`）当前为空，标注为
"pending ODE execution, shell permission unavailable"。

## 五、结论（含对"结论是否合理"的自审）

**本轮没有给出一个具体的"最大高度 = X km"数字，这是有意的，不是遗漏**：

1. 模型输入（大气密度/温度分布）在 100–150 km 高度区间没有真正落地（Level 1 全部
   失败，Level 3 解析近似超出适用范围）；
2. 数值积分（Node 2b 的最后一步）因为权限没有真正执行完；
3. 独立验证基准（§2b 独立性规则）当前也没有可用的第二数据源。

所以本轮能给出的、**不是编造数字**的结论是：*在现有已验证的量纲/边界一致性
（模型方程本身没有写错）前提下，安全下降的可行性判断需要补上真实的高空大气数据
+ 一次完整的数值积分 + 一份独立基准对照，三者缺一，"最大高度"这个数字现在没有
依据给出*。我拒绝把"80–120 km"这种宽泛区间写成"答案"，只如实标注为
"pending，未验证"。

**为什么这个"不下结论"本身是合理的，而不是模型没算出来**：项目的设计目标
（§1 三道防线）是"确定性代码真正跑过"，不是"模型猜一个合理数字"。本轮的产出
是：模型方程通过量纲/边界门禁（可信）、假设逐条显式标记（可复核）、数据源降级
路径完整记录（可追溯）、以及一个**诚实的"当前还差什么才能给数字"**清单。

若后续补上数据源 + 权限重跑，我会对照 Baumgartner 2013 实测（18.4 km 级
真实高空跳伞数据）做独立基准验证，那时的"最大高度"数字才会带有
`verification.benchmark_source` 的量化误差说明，而不是本轮这种"未验证"状态。
