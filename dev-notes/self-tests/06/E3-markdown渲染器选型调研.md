# E3 Markdown 渲染器与离线公式排版选型调研

## 一、现状与问题定位

在 `physics-agent/hooks/trace_visualizer.py`（L233–376）中，现有的 `md_to_html_blocks()` 与 `_md_body_to_html()` 仅实现了极窄的手写子集：
1. **块级语法仅支持 3 种**：
   - `|` 开头的连续管道表格行 → `<table class='md-table'>`
   - `{{figure: <id>}}` 图表占位行 → `<figure class='report-figure' data-figure-id='...'>`
   - `- ` 开头的无序列表行 → `<ul><li>`
2. **所有其他块级语法全部退化为普通 `<p>` 段落**：
   - `### 4.1 卫星的轨道速度`（三级及以下标题 `###` / `####`）未转成 `<h3>` / `<h4>`，而是原样输出 `### ...`；
   - `> 外太阳系探测器常借助...`（引用块 `>`）未转成 `<blockquote>`，且因为先执行了 `html.escape()`，`>` 变成了 `&gt;` 普通文本；
   - `1. ...`（有序列表）未转成 `<ol><li>`；
   - 多行独立公式块 `$$\n...\n$$` 或代码块 ` ```...``` ` 被逐行拆碎成多个 `<p>`。
3. **行内解析存在公式与 Markdown 符号互相污染隐患**：
   - `_inline()` 先跑 `re.sub(r"\*\*(.+?)\*\*", ...)` 再识别 `$...$`，若未来支持 `*italic*` 或 `_italic_`，LaTeX 公式中的下标 `_` 与乘法 `*` 会被误解析为斜体标签。

## 三、最终选型决定与理由

### 结论：**选用方案 C 的工程化升级版（推倒原有的残缺逐行 if-else，重写为“公式保护 + 完整块级状态机 + 离线自包含数学排版引擎”的零依赖 Python 渲染核心）**

**核心理由**：
1. **零环境依赖风险**：经核查 `physics-agent/third_party/portable-runtime/wheels/LOCKED_VERSIONS.txt`，便携运行时内并未预装 `mistune` 或 `markdown`。采用纯 Python 标准库状态机实现，可确保在任何机器、任何离线环境下 100% 免安装直接运行。
2. **彻底保护 LaTeX 公式不失真**：通用 Markdown 库最大的痛点是会把公式里的 `_`、`*`、`\\` 当作斜体或转义符吞掉。自研状态机通过**第一阶段 Token 抽离保护（Math & Code Tokenization）**，先将代码块与 `$$...$$` / `$...$` 原样抽离为占位符，待 Markdown 标题/引用/列表/表格/加粗/斜体全部转换完毕后，再将公式直接渲染为**带离线数学排版 DOM 结构的 HTML（并附带 `data-katex='true'` 与原始 LaTeX 源码属性）**。
3. **一次性覆盖科研报告全部 Markdown 语法分支**：
   - 块级语法：
     - 一至四级标题（`#` / `##` / `###` / `####` → `<h1>`–`<h4>`）
     - 引用块（连续 `> ...` 行合并为 `<blockquote><p>...</p></blockquote>`）
     - 无序列表（`- ` 或 `* ` 连续行合并为 `<ul><li>...</li></ul>`）
     - 有序列表（`1. `、`2. ` 连续行合并为 `<ol><li>...</li></ol>`）
     - 围栏代码块（` ```lang ... ``` ` → `<pre><code class='lang-...'>...</code></pre>`）
     - 独立多行/单行公式块（`$$...$$` → `<div class='math display' data-katex='true'>...</div>`）
     - 管道数据表格（`|...|` + 对齐分隔行 → `<table class='md-table'><thead><tbody>`）
     - 水平分隔线（`---` / `***` → `<hr>`）
     - 图表占位符（`{{figure: <id>}}` → `<figure class='report-figure' data-figure-id='...'>`）
   - 行内语法：
     - 行内代码 `` `...` ``
     - 行内公式 `$...$`
     - 粗体 `**...**`、斜体 `*...*`
     - 行内链接 `[text](url)`
4. **与 E1（公式内联排版）无缝合一**：
   - 既然本地不存在 `vendor/katex/` 且 `file://` 协议禁止 `fetch()` 本地文件，我们在生成的 HTML 中同时提供**服务端预排版 + 客户端自包含 LaTeX 数学渲染器（内联 CSS 数学排版样式 + 内联 JS 公式解析器，支持分式 `\frac`、根号 `\sqrt`、上下标 `^`/`_`、希腊字母、积分求和 `\int`/`\sum`、`\text{}`、比较/箭头算符等全部物理常用符号）**，无需任何外部字体或网络请求，双击打开即可呈现美观、标准的数学公式，同时完整保留 `[data-katex="true"]` 属性以兼容所有既有测试断言。
