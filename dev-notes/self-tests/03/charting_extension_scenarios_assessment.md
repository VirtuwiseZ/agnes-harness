# 图表功能扩展场景常见性评估（仅评估，未实现）

配合 `make_report_figures.py`（当前 5 种 kind：curve / scatter / error_bar /
interval_highlight / heatmap）后续是否扩展，评估第三方反馈提出的 6 个未覆盖场景
在**本项目物理题报告**里的常见性。评估基准：过去 3 轮测试题（2025A 声学/结构、
2025B 弹道、更早若干题）实际出现的分析需求 + 这类竞赛/考试题型的通用特征，
不是泛泛的"matplotlib 能画什么"。

## 逐一评估

### ① 对数/双对数坐标轴 —— 常见性：中高（本项目尚未实际撞上，但物理题里很常见）
- **何时需要**：跨 1 个以上数量级的物理量（声压级 dB、衰减随时间的指数衰减、
  功率谱密度、信噪比 vs 频率）几乎都适合对数或双对数坐标，否则线性坐标下
  低值区域细节全被压缩看不清。
- **本项目证据**：2025A 的 EI 曲线（dB 值）目前用线性轴画（`2025A_eq_curve.png`），
  值域跨度不算极端所以勉强能看，但如果某次题里 dB 跨度超过 ~20 dB，线性轴会
  明显失真。2025B 目前没有需要 log 轴的物理量。
- **判断**：真实需求会来，但不急——取决于下一批题里有没有大跨度量。**优先级：中**。
- **实现成本**：低。matplotlib `ax.set_xscale("log")`/`set_yscale("log")` 一行，
  需要额外处理"数据里有 0 或负值时 log 轴会报错"（这是准确性底线问题，不能
  静默截断/跳过，要像 NaN 一样脚注标注）。

### ② 双 y 轴（twinx）—— 常见性：中（多物理量同一时间/自变量轴、量纲不同）
- **何时需要**：同一自变量（如时间、频率）同时跟踪两个量纲不同的物理量
  （位移+力、温度+压力）。
- **本项目证据**：2025A/2025B 目前的图表都是"单一物理量 vs 另一个物理量"
  或"某扫描参数 vs 响应量"，没有出现过"同一横轴、两个不同量纲的纵轴"的
  真实需求。
- **判断**：物理题里更常见的做法是**拆成两张并列子图**（见⑤），而不是硬把
  两个量纲不同的量塞进同一张图的双轴——双 y 轴在报告里其实是"偷懒对比"，
  容易让读者误以为两个纵轴是同一尺度。竞赛/论文报告更倾向于子图并列。
  **优先级：中低，且要先确认题目真的需要"同图对比"而不是"子图对比"再上**。
- **实现成本**：中。`ax.twinx()` 本身简单，但"左轴标签/右轴标签/图例合并/
  两个 y 轴各自的 5% padding 规则"都需要新设计，不是加一行代码的事。

### ③ 参数化曲线族（同一条曲线扫一个参数、颜色随参数连续变化）—— 常见性：高
- **何时需要**：弹道/振动/热传导里"扫一个参数、每次一条完整曲线"的场景
  （不同发射角对应的完整轨迹、不同频率对应的传递函数曲线族、不同阻尼比
  对应的响应曲线族）——这是物理题里**很常见**的"多条件对比"需求。
- **本项目证据**：2025B 的 `2025B_theta_v0.png` 目前画的是"θ 作为自变量、
  对应的 v0 作为离散点"（6 个候选点），这是参数化曲线族的**退化形式**
  （每个参数只算了一个采样点）。如果题目要求的是"每个 θ 都算出一条完整的
  轨迹曲线"，这就是标准的曲线族需求，目前 5 种 kind 表达不了（每个 kind
  的 `series[]` 是"一条条独立的 x-y 序列"，没有"一族曲线共享一条参数轴、
  参数值映射到颜色/深浅"这种结构）。
- **判断**：**优先级：高**。这是弹道/振动题里最自然的"多工况对比"呈现方式，
  比现在的"离散采样点"更常见。建议作为下一个要实现的扩展（比②④⑥都优先）。
- **实现成本**：中。数据层面需要新字段（`param_axis` 描述"扫的是哪个参数、
  取值范围、每步对应的曲线数据"），渲染层面需要固定色带（viridis 或类似）
  把参数值映射到颜色——这一步的"判断"是纯呈现层（色带选择），跟现有
  `role` 风格表同级别，不涉及物理判断。

### ④ 茎图/频谱图（FFT 结果）—— 常见性：低-中（取决于题目里有没有"信号/振动频谱"分析）
- **何时需要**：把时域信号做 FFT、展示"各频率分量幅值"（振动频谱、声学频谱）。
- **本项目证据**：目前没有一道题要求过"把这个信号做频谱分析"。2025A 的
  声学内容是"模态/EI 曲线"，不是 FFT 频谱。
- **判断**：**优先级：低**，除非后续题目明确涉及振动/信号的频谱分析。
  FFT 结果是标准的"频率 vs 幅值"对数幅值条形/阶梯图，形态接近现有
  `error_bar`/`scatter`，只是 x 轴是频率（可能需要对数，见①）。
  不需要单独新发明一种 kind，等真实题目需要时按"scatter/curve + 对数x轴"
  组合实现即可，不需要预先开发。

### ⑤ 多子图（subplot）布局—— 常见性：高（"原始 vs 处理后"对比几乎必然用到）
- **何时需要**：对比两个"同一批数据的不同处理阶段"（滤波前后、理论 vs
  拟合、有扰 vs 无扰），子图并列是最直观、也是报告里最常见的对比方式。
- **本项目证据**：目前没有一道题明确需要"同屏对比两张图"，但这是物理
  分析报告里非常常见的排版需求（"原始数据"和"去掉噪声后"放上下两格对照）。
- **判断**：**优先级：高**。且实现上其实可以**复用现有 5 种 kind**——子图
  本身不需要新的 kind，需要的是一个"这张报告图 = N 个子图，每个子图各自
  是一个现有 kind 的 spec"的嵌套结构（`subfigures: [spec1, spec2]`），
  每个子图还是走 `_draw_1d`/`_draw_heatmap` 不变。改动集中在
  `render_all` 外层多一层 dispatch，不动底层渲染逻辑，风险低。
- **实现成本**：中（主要是 schema 要加一层嵌套结构 + 图注排版，底层
  5 种 kind 的绘制代码不用改）。

### ⑥ 极坐标（声场方向性、辐射图样）—— 常见性：低（本项目题型里少见）
- **何时需要**：天线条、声学方向图、旋转对称问题（波束方向性、辐射指向性）。
- **本项目证据**：没有一道题涉及"方向性"类问题。
- **判断**：**优先级：低**。这是最偏领域（电波/天线/特定声学方向图）的
  需求，除非项目明确要覆盖这类题，否则不值得现在开发。真需要时
  `ax.setProjection("polar")` 本身很简单，但"什么情况下选极坐标而不是
  笛卡尔坐标"这个判断比前 5 项都更依赖题目具体上下文，不适合做成
  机械默认规则。

## 结论（按优先级排）

1. **曲线族（③）和多子图（⑤）**：常见性高，且③是弹道/振动题的自然需求，
   ⑤是所有报告类项目（不只是物理题）都会用到的通用排版能力——建议这两个
   优先排进下一个实现批次，**但先等 5 种 kind 打磨完、真实数据验证过再动手**
   （这正是你说的"等打磨好当前 5kinds 再按需补充"的节奏）。
2. **对数坐标（①）**：常见性中，实现成本低，但需要跟"数据里有 0/负值时
   log 轴会崩"这个准确性细节一起设计，不适合单独抢跑，等③⑤做完后一并处理。
3. **双 y 轴（②）**：常见性中低，且和⑤（子图）有功能重叠——同一需求
   （同屏对比两个量纲不同的量）用子图往往比双轴更清晰，建议先实现⑤，
   真正撞见"必须同轴对比"的题再补②，不预先开发。
4. **频谱图（④）和极坐标（⑥）**：常见性低，且④其实可以靠"现有 kind +
   对数x轴"覆盖，⑥是偏小众领域需求，都不需要提前开发，撞到再评估。
