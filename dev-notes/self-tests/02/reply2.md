在补充 DIM_ALIAS 词典的同时，为了避免后续频繁陷入“遇到新物理量就报 KeyError”的被动维护循环，请在量纲检查引擎的架构层注意并落实以下五点工程细节：

1. 别名表解析的回退机制（Fallback Mechanism）
不要让代码强依赖于静态字典查找。当用户传入未定义的维度名时，不要直接触发 KeyError，请设计两级回退策略：
- 一级回退（原生单位解析）：如果 key 不在 DIM_ALIAS 中，直接尝试调用 `ureg.parse_units(key)`。这允许用户直接传入复合单位串（如直接传 "J/kg"、"N*s" 或 "m/s^2"）来定义物理量。
- 二级回退（Pint 原生量纲解析）：尝试调用 `ureg.parse_expression(f"[{key}]")` 或允许用户传入带中括号的 Pint 官方量纲语法（例如 "[length]**2 / [time]**2"）。
如果以上尝试全部失败，再抛出带有清晰建议的异常（提示用户直接传入单位表达式，而非未注册的自然语言别名）。

2. SymPy 导数项（Derivative）的自动量纲推导
由于该工具常用于动力学 ODE 场景，方程中必然存在 `Derivative(y(t), t)` 或 `Derivative(u, x, 2)`。请确保引擎遇到 SymPy 的 Derivative 对象时，能递归解析出被导符号与求导变量的量纲，并自动计算出商：
- $\text{dim}\left(\frac{d^n y}{d t^n}\right) = \frac{\text{dim}(y)}{\text{dim}(t)^n}$
不能将求导表达式降级为未知符号去查表，必须在符号 AST（抽象语法树）层面自动合成其导出量纲。

3. 超越函数与无量纲约束校验
在解析非线性物理方程（如阻力项中的指数、三角函数衰减）时，请在 AST 遍历中加入约束检查：所有作为 `exp()`、`log()`、`sin()`、`cos()` 参数的子表达式，其量纲必须严格化简为无量纲（dimensionless）。若检测到带量纲参数输入超越函数，应提前中断并输出明确的数学违规报错。

4. 弧度（rad）与转矩/能量的歧义规避
在纯 SI 体系中角度为量纲一，但 Pint 内部保留了 `[radian]` 量纲。这导致力矩（$N \cdot m$）与能量（$J$）虽然在 SI 基本单位上相同，但在某些带角度的旋转动力学方程中可能会产生潜在的量纲不匹配。请在引擎中明确设定处理策略：对于角位移与角度输入，统一将其量纲基底按弧度规范化，或在最终齐次性比对时明确是否执行 `.to_base_units()` 并兼容无量纲化。

5. 错误诊断输出的可读性
当方程齐次性检验失败时，不要只抛出布尔值或笼统的 DimensionalityError。请将 SymPy 方程按项（针对 `Add`）或左右两侧（针对 `Equality`）拆分，分别打印出每一项归一化后的基本量纲表达式（如 `[mass] * [length] / [time]**2`），方便使用者一眼看清是方程中的哪一项丢掉了系数或除错了变量。
