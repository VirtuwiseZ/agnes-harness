## A. 报告呈现层（HTML/网页）

A1. **不要再给用户看 `audit_logs`**（"trace 对照"和"数据快照"这两个 UI 块全部删掉）。
   - 背景：这个"哈希/seq 对照表"对用户没用"。报告需要呈现的是针对物理问题的分析过程，以体现最终结论的可靠性。AGH运行trace的作用是辅助AI整理报告、确保流程不是杜撰而是真实的；而具体呈现给用户/报告读者的“可靠性证据”应该是AI做物理分析的过程具体是怎样的，而非每一步骤对应的哈希/seq值。

A2. **报告里的公式没有用 LaTeX，markdown（特别是表格）没有渲染**；需要校验机制，且**校验方式不是 Python 程序，而是把要求注入给 AI、确保它在写报告前有收到指导、写完报告后自行检查，没问题才发给用户**（不能只靠"整个分析过程开始时"的上下文提醒，要在**报告生成前再次提醒**）。
   - 本次会话已核实的现状（`trace_visualizer.py` 实际代码，test5 HEAD `11a41103`）：
     - LaTeX：`_md_body_to_html()` 的 docstring 自称"$$-fenced math as plain `<pre>` — no LaTeX rendering"，但**函数体里根本没有 `$$` 围栏的分支**——实际只有 `{{figure:}}` 占位符、`- ` 列表两条路径，其余所有行（含 `$$` 公式行）都走 `<p>`+`html.escape()`；`render_html()` 的 `<head>` 里只有内联 `<style>`，没有任何 KaTeX/MathJax 引入（全文检索 `katex`/`mathjax`/`latex` 命中 0）。
     - test5.1 实际报告（`report_2013A_jupiter_flyby_run2.md`）里**没有出现过任何 `$`、`\(`、`\[` 数学定界符**——公式全部写成 Unicode 纯文本近似（如 `v_out² − v_inf² = ...`、`√((v_moon + v_rel·cos δ)² + ...)`），也就是说问题比"没接 KaTeX"更靠前一步：写作层压根没采用数学排版约定，加 KaTeX 也找不到可渲染的公式边界。
     - 管道表格：test5.1 报告源文件（`.md`）里 11 处 `|---|` 分隔的管道表格，渲染进 HTML 后全部以字面 `| Io | 17.332 | ...` 纯文本形式出现在普通 `<p>` 标签里（已核实具体 HTML 片段），`_md_body_to_html()` 对这个语法子集没有实现（docstring 自己声明只支持"段落/`-` 列表/`**bold**`/反引号/`$$` 围栏公式（实际未实现）"）。

A3. **报告语言风格不够严肃**：大量括号备注的无用文字（原文举的例子：`1. 摘要（先给结论）`），"不想看到 AI 一直解释、显摆自己如何践行了项目设计理念"，要严肃的"科研报告"风格，可以参考**开发者提供的比赛范文**总结出一个模板。
   - 本次会话已核实的现状：test5.1 报告 `report_2013A_jupiter_flyby_run2.md` 里小节标题普遍带自我评价式括号（`## 1. 摘要（先给结论）`、`## 4. 建模 —— 核心恒等式（本轮最硬的结论）`、`### 5.2 两次串联飞掠（chained，本轮新增，真正可能"救回"的机制）`），全文检索出 112 处全角括号，其中 20 处是"本轮/新增/核心/直接发现/不是...而是"这类自我指涉词，全部出现在小节标题或紧随其后的导语里。
   - 已有相关产出：1009 §3.1 新建的 `program-design/knowledge/report_structure_guide.md`（test5 HEAD 确认存在）提炼了 3 份范文（2010/2020/2023）的 8 章标准结构 + 3 条行文风格约束（结论先行/假设显式化/验证独立于建模），test5.1 实际报告基本按这个结构执行（8 章顺序对齐、假设章节逐条编号 1–7、验证章节独立于建模数据源）——**但这份指南的 3 条风格约束里没有一条覆盖"小节标题本身要干净、不带元注释"这一层**，这是 test5.1 暴露出来的、指南本身没写全的缺口。

A6. 之前会话中AI提出的设计：
   - **Q1 定论**：`problem_state.json` 不需要向用户展示，报告上不用显式体现，仅留作内部核对 AI 运行流程、调试数据追溯用；**记一条备忘：可能要在别的设计文档中去掉对"把它放进报告"的强调**，防止后来 AI 又把它显式塞进报告。
   - **Q2 定论**：报告正文里不放行内链接；**每节末尾放一个名字叫"本节相关文件"的下拉列表**（对应 HTML 的 `<details>`/`<summary>` 折叠块，不是真的 `<select>` 下拉框），逐条对应写清楚"文件（带链接，点击查看源代码）— 作用描述 — 迭代记录（带链接，点击查看 AI 各次调用这个程序的输入输出、调试/运行过程，这里可能包含报错记录）"。

# AI 的评估与建议（和前面的想法对应）

## A1：删掉"核验附证/数据快照"

判断：直接删，不保留任何 fallback（跟 A6-Q4 一致）。**但删之前需要先跟 A4/A6-Q2 的新需求对好接口**：A4 的"本节所使用文件"下拉块要展示的是"文件名（可点）— 作用描述 — 运行记录（可点，含输入/输出/报错）"，这条数据跟 `audit_logs`（调用元数据，artifact_id/seq/参数摘要）不是同一类东西，也**不能**继续挂在 `problem_state.json` 的 `audit_logs` 字段上（A6-Q1 已经定论：`problem_state.json` 不再向用户展示）。也就是说，**删掉 A1 的两个旧块和新增 A4 的"本节所使用文件"块，是同一件事的两面**，不是两个独立改动——删旧块的直接原因是"它的信息密度/可信度（哈希对照表）远低于 A4 要的新信息密度（真实源码+真实运行流水）"，所以正确做法是**新块落地时顺手删旧块，一次性完成，不留过渡期**。

## A2：公式/LaTeX + markdown 表格渲染，以及"AI 自查"校验机制

判断（分两层，本次会话已核实过现状，直接给出可执行方案，不重复论证）：

1. **写作层（先解决"公式根本没写成 LaTeX"这件事，比"渲染层没接 KaTeX"优先级更高）**：在 `report_structure_guide.md`（1009 §3.1 已建的这份文件，不新建）里**新增第 4 条行文风格约束**（原文 3 条是"结论先行/假设显式化/验证独立于建模"，都不涉及公式排版约定）：
   - 约束 4：**所有数学公式/符号表达式，必须用 LaTeX 定界符（行内 `$...$`、独立行 `$$...$$`）书写，不使用 Unicode 上下标字符（如 `²`、`√`、`δ` 拼在正文里）冒充公式排版**；
   - 约束 5（顺带补上本次核实的另一缺口）：管道表格（`|` 分隔）必须按真实 markdown 表格语法写（表头行 + `|---|` 分隔行 + 数据行），不允许把表格数据写成普通文本行——这一条本身不需要"新增"，因为 test5.1 报告源文件里表格写法的**语法本身是对的**（确实用了 `|---|`），问题纯粹出在渲染层没实现，所以下面第 2 点才是真正要改的地方，第 1 点的"约束 5"只是把"写法规范"钉死，防止未来某次 Agent 又把表格写成纯文本行。
2. **渲染层（`trace_visualizer.py` 的 `_md_body_to_html()` 升级）**：这是生产 hook 改动，跟 §3.2 1009 里预留的"该修未修"是同一批，本次一并做：
   - `render_html()` 的 `<head>` 注入 KaTeX（自包含，不引外部 CDN；离线打开时公式退化为原始 LaTeX 源码显示，不会让页面崩溃，跟现有图表"缺图不白屏"的处理原则一致）；
   - `_md_body_to_html()` 新增管道表格分支（`|` 开头的连续行合并成 `<table>`）；
   - **改完必须跑一遍 `dev-notes/self-tests/03/` 相关验收脚本**（1009 §3.2 明确写的"改生产代码 + 没有对应的验收测试复跑"这条铁律），确认没把现有图表内联、`{{figure:}}` 占位符替换等逻辑改坏。
3. **校验机制（A2 原文"校验方式不是 Python 程序，而是把要求注入给 AI"）**：判断这条**跟第 1、2 点是三件不同的事，不能混**：
   - 第 1 点（写作层）是"SKILL.md/`report_structure_guide.md` 里写死的规定，Agent 写报告时要遵守"——靠的是**事前注入**（写进指南/约束文档本身，Agent 每次走 Node 3 前会读到），不是靠"报告生成前再提醒一次"的临时上下文。
   - 第 2 点（渲染层）是"改 `trace_visualizer.py` 代码"，跟"校验"无关，是修能力缺口。
   - **原文 A2 说的"校验"（写完报告后 AI 自行检查）指的不是"检查公式有没有渲染对"（那是渲染层的事，Agent 改不了渲染层代码），而是"检查自己的写作是否遵守了约束 4/约束 5 这类规范"**——这确实应该做成"Agent 写完报告后、发给用户前，自己对照 `report_structure_guide.md` 逐条自查一遍"的**事后自查清单**，不需要写 Python 程序去校验（Python 程序只能校验"符不符合语法"，校验不了"符不符合行文规范"这类判断性标准），跟 A2 原文"校验方式不是 Python 程序"的判断一致。这条会写进 `SKILL.md` Node 3 的描述里（跟"报告生成前再次提醒"这一句合并在同一个动作里：Agent 在 Node 3 最终整合报告**之前**先读一遍 `report_structure_guide.md` 的 4/5 条约束，**之后**（发出报告给用户前）对照自查一遍，两步都是同一个节点内的动作，不需要跨节点）。

## A3：语言风格/严肃性

判断：这是 A2 的"写作层"里**漏掉的第 6 条约束**（结论先行/假设显式化/验证独立/公式排版/表格写法 5 条都覆盖了，唯独"标题要干净、不带元注释"这条没写），test5.1 实际暴露出来的"（先给结论）（本轮最硬的结论）"这类标题，是**约束没写到这一层，不是约束写了但没被执行**——所以修复方式跟 A2 一样：往 `report_structure_guide.md` 里新增第 6 条约束（"小节标题只写该节主题名，不写'这是新增的/这是本轮最硬的结论/先给结论'这类自我评价/元注释；'本轮相对上一轮新增了什么'集中放在报告开头一段'本轮说明'里说一次即可，不在各节标题里重复"），**不需要新建模板**——因为 1009 §3.1 的 8 章标准结构（摘要→引言→假设→建模→验证→结果→优缺点→讨论）本身已经是从 3 份范文里提炼出来的"结构模板"，原文 A3 问的"可以参考我提供的比赛范文，总结出一个模板？你考虑一下"，判断：**不需要额外再总结一个新模板，复用 `report_structure_guide.md` 现有的 8 章结构 + 补上这次新加的 3 条约束（4/5/6 条）就够了**，再另起一份模板文档会造成 1009 §2.5 已经修掉的"同一信息两处并存"问题的复发。
