## 一、 技能解耦与 1+9 治理体系演进决策（10/09）

### 1. 核心设计痛点
早期项目采用单体大型 `SKILL.md`，动辄数万字。大模型在单次会话中处理长上下文时，容易产生指令注意力分散、忽略执行约束或在不同阶段规则间混淆。

### 2. 关键决策与实现方案
- **平台零侵入扩展原则**：严格基于 Agnes Harness 原生的 Skill 与插件接口，不修改宿主平台任何源代码；
- **拆分为“1 个流程路由器 + 9 个专业子技能”**：
  - 由原生路由器插件（`physics-agent-orchestrator`）在启动时自动挂载，负责识别物理任务后分阶段提示大模型读取对应子技能；
  - 9 个专业子技能按阶段划分职责：基础治理与状态检查（`physics-agent-governance`、`physics-state-check`）、任务解构与推导（`physics-pipeline`）、物理检验（`physics-defense-lines`）、审计留痕（`physics-auditability`）、报告撰写与绘图（`physics-report-writing`、`physics-report-charting`）、环境受限自愈（`physics-permission-shortfall`）及文献结构化解析（`physics-doc-parsing`）；
- **渐进式披露收益**：使每次注入大模型的上下文仅包含当前步骤所需的具体约束，显著降低推理上下文负担，避免偏航。

## 二、 交互式双栏离线学术报告重设决策（10/11）

### 1. 核心设计痛点
早期报告直接采用平铺长文本，读者无法验证正文中的数值究竟出自哪一次脚本执行；外部 CDN 加载公式容易在无网环境下产生空白或源码暴露；内部图例容易遮挡数据曲线。

### 2. 关键决策与实现方案
- **双栏常驻交互排版架构**：
  - 左侧为主研究报告正文，采用学术章节格式；
  - 右侧为常驻资产与执行记录窗格，支持手柄在 340 像素至 1100 像素以上自由拉伸宽度，提供四档常用宽度预设及日志自动折行开关；
- **100% 离线自包含机制**：
  - 数学公式排版样式完全内联（内联 KaTeX 样式子集），彻底移除所有外部在线 CDN 链接；
  - 科学图表采用纯矢量 SVG，所有图例统一移至绘图区域外侧的独立 Flex 胶囊条中，实现数据曲线零遮挡；
- **正文蓝链时序热跳转（Hot Jump）**：
  - 正文中的数据结论与调试记录配有可点击链接；
  - 点击后右侧内嵌的时序列表平滑滚动居中并触发脉冲高亮，展示原始终端输入命令、实际控制台回显、执行耗时与时间戳；
- **跨标签页无重载唤醒（BroadcastChannel）**：
  - 报告顶部支持通过浏览器进程间通信，原地切换已打开的 AGH 会话标签页。

## 三、 四重确定性物理工程防线确立备忘（10/13）

### 1. 核心设计痛点
大语言模型基于概率预测生成词元，缺乏物理公理与数学计算引擎，直接让模型计算物理量极易产生非物理数值、量纲失配等幻觉。

### 2. 关键决策与实现方案
- **免口算分工原则**：大模型仅负责理解物理机理、推导控制方程逻辑并编写求解程序，所有的具体代数运算、微分方程数值积分全部交给外部独立的 Python 解释器实际运行；
- **符号量纲齐次性门禁（`dimensional_gate.py`）**：
  - 调用 SymPy 解析方程语法树，利用 Pint 物理单位库严格检验等式两侧基本量纲是否配平；
- **物理边界门禁（`boundary_gate.py`）**：
  - 通过 `boundary_spec.json` 自动化测试极端退化极限（如零引力、无穷远飞掠、质量无关性极限）及全域参数单调性扫描，杜绝除零发散与虚假伪收敛；
- **出厂质量质检门（`report_quality_check.py`）**：
  - 在最终交付报告前执行 8 项程序化扫描，拦截元导语与底层调试代码，确保数学公式已通过内联代码离线渲染，图例无遮挡；
- **状态机与审计留痕（`problem_state.json` + `trace.jsonl`）**：
  - 任务全生命周期的假设前提、模型选择与检验结果均增量记录于状态机，底层自动记录具备毫秒级时间戳与 SHA-256 签名的只读时序账本。

## 四、 关键工程避坑与问题备忘 (Troubleshooting Notes)

### 1. 工具调用参数嵌套校验失败
- **问题机理**：部分第三方大模型服务商或代理网关在处理 Function Calling 时，会将实际参数序列化为字符串并强制包裹在 `{ input: "..." }` 或 `{ input: { ... } }` 外壳中；而工具本身的 JSON Schema 并没有 `input` 属性，导致宿主原生校验报错 `TOOL_ARGS_INVALID`；
- **解决方案**：在平台层 `tool-args.ts` 引入 `unwrapToolArgs()` 函数，在校验前执行安全解包，若外层有冗余的 `input` 包装且原 schema 未定义 `input`，则自动解开包装取出真实参数。

### 2. 本地代理虚拟网卡 (TUN) 与 `web_fetch` 工具拦截
- **问题机理**：代理软件开启虚拟网卡（TUN 模式）且开启“覆写DNS / Fake-IP”时，域名被劫持为保留网段 `198.18.0.0/15`，被宿主安全库判断为非公网 Unicast 地址，触发 SSRF 拦截并抛出 `WEB_BLOCKED_URL`；
- **解决方案**：
  - 方案 A（用户配置）：建议用户在代理客户端中关闭“覆写DNS”（即改用真实 DNS / Redir-Host 模式），实测此时公网 Unicast IP 顺利通过安全校验，出站流量仍由 TUN 虚拟网卡代理加速，工具完全恢复正常；
  - 方案 B（代码自愈）：通过轻量 Python 脚本直接调用操作系统底层网络套接字（Socket）直连穿透，不受宿主 TypeScript 适配层拦截。

### 3. Windows PowerShell 5.1 CP936 编码崩溃
- **问题机理**：在中文 Windows 默认环境（代码页 CP936/GBK）下，PowerShell 5.1 解析未带 BOM 的 UTF-8 多字节汉字字符串时容易出现截断与引号吞噬，导致 `MissingEndCurlyBrace` 或 `NativeCommandError` 语法报错中断；
- **解决方案**：所有交付的核心部署脚本（`doctor.ps1`、`setup.ps1`、`start.ps1`）全部采用纯 ASCII 语法编写，禁止在脚本内硬编码任何非 ASCII 字符；多行 Git Commit 文本统一采用 `git commit -F <file>` 外置文件调用。

### 4. 交付末尾自言自语与死循环防范
- **问题机理**：长任务收尾时，若未明确限制输出格式，模型容易在文末添加客套寒暄、自问自答，甚至误将自身上一轮输出当成用户追问而陷入自回复死循环；
- **解决方案**：在 `physics-agent-governance` 中设立“结题即静默铁律”与“C1 首段双路径开门见山交付规范”，要求模型直接给出 HTML 报告与 Markdown 源码的本地绝对路径，紧接着直接引用预设说明文本后立即结束输出，禁止输出任何额外客套与发散。
