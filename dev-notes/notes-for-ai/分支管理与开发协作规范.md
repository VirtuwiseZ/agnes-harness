> **归档位置**：`dev-notes/notes-for-ai/分支管理与开发协作规范.md`  
> **制定日期**：2026-10-16  
> **适用对象**：参与本项目开发、测试、发版与维护的所有 AI 智能体及协作者。

## 一、 分支角色定位与职责矩阵

本项目代码库确立了清晰的五类分支分工体系，严禁越权或混用各分支职责：

| 分支名称 | 分支定位 | 资产包含范围 | 读写与修改权限规则 |
| :--- | :--- | :--- | :--- |
| **`physics-agent`** | **主开发基线分支** | • 代表最新版本的项目核心资产；<br>• 包含全部代码、技能、安装套件及面向开发者的资料（`dev-notes/` 全量档案）。 | • **日常主开发阵地**；<br>• 小规模、低风险的日常调整与修复可直接在此分支进行。 |
| **`pa-<内容>-dev`** | **特性/大改动研发分支** | • 承载特定重大特性、重构或高风险试验的临时工作区；<br>• 继承当前主开发分支的完整资产。 | • **规模与风险较高的任务必须新建此分支**（如 `pa-minimal-dev`）；<br>• 本地验证通过并经开发者确认后，方可合并回合主开发分支。 |
| **`physics-agent-release`** | **用户发布整理分支** | • **仅包含面向最终用户的生产级交付物**；<br>• 包含安装向导、一键启动器、自检脚本、核心技能与文档；<br>• **彻底排除 `dev-notes/`**（无内部日志、备忘、草稿与测试数据）。 | • 用于整理发布包与向主分支发起 PR；<br>• **严禁向此分支直接提交开发调试垃圾或未脱敏档案**。 |
| **`main`** | **稳定生产主分支** | • 生产级发布基线；<br>• 对外展示的 GitHub 仓库主页。 | • **主支只能接受来自 `release` 分支的 PR**；<br>• **【刚性铁律】只有开发者本人可以手动在 GitHub 网页发起并合并 PR，AI 绝对不能主动修改或向 `main` 推送代码**。 |
| **`ability-test7`** | **独立工作区测试分支** | • 绑定独立测试工作区 `E:\agh-test`（端口 4180）；<br>• 承载环境隔离与跨会话整体测试。 | • 专门用于开发者进行全系统级别的独立环境回归走查；<br>• 平常开发中的单元自检直接在对应开发分支完成即可，无需频繁占用该分支。 |

## 二、 场景化开发与协作工作流

### 1. 规模与风险较小的日常改动
- **适用场景**：修正已知的小 bug、更新常数表、微调技能提示词、修补文档错别字等；
- **执行方式**：可以直接在 **`physics-agent`** 主开发分支上检出、修改并进行本地验证；
- **自检要求**：提交前必须运行 `python physics-agent/hooks/skill_bom_check.py` 确保技能编码合规，并运行 `scripts/doctor.ps1` 确认环境健康。

### 2. 规模较大或具备探索风险的重大改动
- **适用场景**：重构底层安装程序、重构报告渲染引擎、引入新的门禁机制、调整底座核心通信逻辑等；
- **执行方式**：
  1. 从最新的 `physics-agent` 分支检出全新的专属特性分支：  
     `git checkout -b pa-<特性简述>-dev`（例如 `pa-minimal-dev`）；
  2. 严格在本地分支开展修改与验证；
  3. **【铁律】未获得开发者明确授权前，禁止擅自 commit，绝对禁止 push**；
  4. 待开发者审阅并确认满意后，再执行本地提交，并合并回 `physics-agent` 分支。

### 3. 日常测试与独立工作区测试分流
- **日常小测试**：直接在当前开发分支（`physics-agent` 或 `pa-*-dev`）对应的本地工作区内运行轻量单元测试或验证脚本；
- **独立环境整体回归测试**：当需要模拟“一台独立的全新机器”进行完整端到端长流程走查时，切换至绑定在 `E:\agh-test` 的 `ability-test7` 分支，利用独立端口（4180）与独立配置目录（`~/.agh-physics`）进行无先验干扰的整机测试。

## 三、 对外发布与 Pull Request 核心规程

当主开发分支上的新特性或修补项经过充分验证、准备对外发布新版本时，必须严格执行以下四步标准化流程：

```
第一步：在 physics-agent 上确认开发收官与环境通过
   │  • 验证所有功能就绪，skill_bom_check 与 doctor 均为 EXCELLENT 评级
   ▼
第二步：选择性同步生产交付文件至 physics-agent-release
   │  • 切换至发布分支：git checkout physics-agent-release
   │  • 将生产代码、安装程序与文档从主开发分支同步检出
   │  • 【核心红线】坚决排除 dev-notes/ 目录（保持发布分支 0 dev-notes）
   ▼
第三步：在本地重新打包与编译安装套件
   │  • 编译最新 AI_Physics_Agent_Setup.exe 与 Uninstall.exe
   │  • 打包 release/*.zip 发行包并生成校验码
   │  • 推送至 GitHub：git push origin physics-agent-release
   ▼
第四步：由开发者本人手动审查并向 main 发起 PR
      • 【核心铁律】AI 绝对禁止直接向 main 推送或自动发起 PR
      • 由开发者本人在 GitHub 网页端点击 "Compare & pull request"
      • 审查文件变更列表（确认 0 内部档案杂质），使用 Squash and merge 合并入 main
```

## 四、 智能体行为守则（AI Compliance Invariant）

任何接入本项目的 AI 模型在协助开发者处理代码时，必须遵守以下指令底线：
1. **知晓自己的分支位置**：在执行任何文件增删与暂存前，必须先确认当前所处的分支；
2. **严禁越界修改主分支**：`main` 分支是神圣基线，严禁在 `main` 上直接开展未经验证的开发，严禁越过开发者私自修改 `main`；
3. **保护发布分支的纯净度**：`physics-agent-release` 分支必须始终维持与 `dev-notes/` 物理隔离的状态；
4. **尊重历史档案**：`dev-notes/` 下的架构共识、AI 指南与自测案例是项目宝贵的技术资产，在主开发分支上必须妥善维护，禁止擅自清空或破坏。
