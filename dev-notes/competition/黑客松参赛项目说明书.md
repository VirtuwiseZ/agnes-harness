## 一、 项目背景与问题来源

### 1. 行业痛点：传统大模型处理科学与工程问题的根本局限
在传统问答式的大语言模型应用中，模型在面对物理建模、航空航天轨道计算、高维动力学分析等严谨科学问题时，普遍存在以下致命缺陷：
1. **“一本正经胡说八道”（物理幻觉严重）**：模型倾向于直接凭统计概率生成看似合理的公式与数值，缺乏底层的量纲校验与真实数值计算支撑，易出现“速度加加速度”、“负质量”等非物理低级错误；
2. **缺乏连续执行与工具调用闭环**：单轮对话无法支撑“背景调研 $\to$ 建立假设 $\to$ 方程推导 $\to$ 数值求解 $\to$ 独立交叉验证 $\to$ 异常回滚 $\to$ 学术报告生成”的复杂科研全生命周期；
3. **黑盒不可追溯、无真实审计留痕**：模型生成的数值结论无法回溯至具体的代码执行、输入参数及数据来源，缺失严肃同行评议所需的不可篡改证据链；
4. **离线环境脆弱**：产出的图表与报告往往依赖外部在线 CDN 或本地孤立服务，在脱网或受限计算环境下公式乱码、图表崩塌。

### 2. 项目使命
本项目基于 **Agnes Harness（AGH）**，构建了一套**具备确定性物理工程防线、多步连续自适应执行能力、出厂前刚性质量门禁与结论防伪全溯源的科研级物理智能体（Physics-Agent）**。该智能体能够自主承接复杂的物理竞赛与工程分析题目，在无人工干预的情况下完成高保真、可复现、可审计的科学研究闭环。

### 1. “1 插件 + 1 主控 + 8 子 Skill”解耦架构
- **流程路由插件（`physics-agent-orchestrator`）**：作为 AGH 运行时插件（`inject: ['skills']`），根据题目性质动态激活路由表，提醒智能体按节点顺序读取子技能；
- **主控协议（`physics-agent-governance`）**：统筹全流程规范、参考解答物理隔离原则（§5）及交付前自检闭环；
- **八大专业子 Skill**：
  - `physics-state-check`（任务隔离目录与状态账本初始化）
  - `physics-defense-lines`（量纲门、边界门、退化极限防线）
  - `physics-pipeline`（第一性解构、费米估算、最简基线优先、数据源路由）
  - `physics-auditability`（原子化执行留痕、SHA散列与中文运行资产）
  - `physics-report-charting`（出版级绘图规范、外置图例条、公式自包含内联）
  - `physics-report-writing`（八章学术论证结构、七条行文铁律）
  - `physics-permission-shortfall`（便携运行时兜底与权限受限自愈）
  - `physics-doc-parsing`（外部科研文献/图纸按需解析）。

### 2. 连续执行六节点流水线（Pipeline）
1. **Node 1（任务理解与第一性解构）**：提取研究对象、外场相互作用，提炼一句话核心目标，完成费米/数量级先行估算，初始化 `problem_state.json`；
2. **Node 1.5（公开数据源路由）**：按权威三档分类决策树选用数据（Level 0/2 离线优先 $\to$ 官方 REST API $\to$ 人工协作），支持 TUN 代理网卡自适应代码直连穿透；
3. **Node 2a（机制匹配核验）**：对知识库方法模板进行逐行物理机制匹配检查，杜绝将大气阻力套用在天体散射上的“张冠李戴”；
4. **Node 2b（建模求解与四重刚性防御门禁）**：编写任务专属独立 Python 模型，执行 SymPy 量纲一致性检验、极限退化边界检验、独立解析方法交叉核验；
5. **Node 3（增量学术报告合成）**：按八章学术标准增量汇总，严格执行七条行文铁律（零黑话、无元导语、公式 LaTeX 排版、管道表格、提炼主导规律与失效边界）；
6. **Node 4（双栏离线排版与热交互引擎）**：由 `trace_visualizer.py` 编译产出单文件离线 HTML，内置 Section 9（质量审计与四大返工复盘）、会话三轨甘特图及蓝链毫秒级热跳转。

## 三、 三类运行工况与验证证据链（大赛重点考察指标）

为满足大赛对“正常情况、边界情况、失败情况”三类运行样例的严格验收要求，本项目以 **06 号自测算例（木星卫星引力弹弓减速调研）** 及历史真实走查记录提供全链路验证证据：

### 1. 正常工况（Normal Execution Case）
- **测试场景**：探测器以 $v_\infty = 20\ \text{km/s}$ 入射木星系，评估四颗伽利略卫星的单次飞掠最大减速量及推进剂节省比例；
- **执行过程**：
  - 智能体通过 Node 1 提炼目标，估算木卫一绕木速度约 $17\ \text{km/s}$，理论减速上限可达 $24\ \text{km/s}$ 量级；
  - Node 1.5 路由至 JPL/IAU 标准常数表（$G_J = 1.2669\times10^8\ \text{km}^3/\text{s}^2$、木卫一至木卫四轨道半长轴）；
  - Node 2b 建立双体弹性动量交换模型，成功求解：
    - 木卫一（Io）单次飞掠最大减速 $\Delta v_{probe} = 24.51\ \text{km/s}$，对 $15.59\ \text{km/s}$ 入轨需求覆盖率达 $157.2\%$；
    - 化学燃料质量分数由 $98.93\%$ 降至 $0\%$（免化学动力直接捕获）；
  - 产出出版级矢量图表（偏转角曲线族、推进剂柱状图），图例完全外置（零遮挡）。
- **核验结论**：数值计算精度高、物理机制清晰，完全通过独立齐奥尔科夫斯基火箭方程交叉验证。

### 2. 边界与极端工况（Boundary & Degenerate Limits Case）
- **测试场景**：验证模型在物理极端或退化条件下的数学自洽性与物理退化行为；
- **边界探针设计（`boundary_spec.json`）**：
  1. **零引力退化极限（Zero Gravity Limit）**：令木星引力常数 $G_J \to 0$，卫星公转速度 $v_{moon} \to 0$。模型自动求解输出 $\Delta v_{probe} \to 0.0\ \text{km/s}$，自洽证明没有引力动量库时无法发生弹性借力加速/减速；
  2. **探测器质量无关性极限（Probe Mass Independence）**：将卫星与探测器质量比放大 $10^6$ 倍（模拟更轻探测器）。模型输出 $\Delta v_{probe} = 24.51\ \text{km/s}$ 严格保持恒定，验证双体弹性散射极限下减速量仅取决于卫星本底速度的物理定论；
  3. **渐近速度全域单调性扫描（Monotonicity Sweep）**：令入射速度在 $10 \sim 30\ \text{km/s}$ 范围内连续扫描，覆盖率单调平滑下降，无发散或奇点。
- **核验结论**：边界门禁（`boundary_gate.py`）测试结果 100% PASS，证明模型在物理边界处无任何非物理截断或人工经验拟合破绽。

### 3. 失败、异常与自适应纠错工况（Failure & Error-Recovery Case）
在面对工具报错、参数异常或网络阻断时，智能体**坚决拒绝无条件盲目执行或伪造数据**，通过四项核心返工重制机制实现了主动回滚自愈：
- **过程 A（数值打靶截断异常与回滚）**：首轮积分截断半径过小导致非物理能量阶跃，边界门禁发出阻断告警，流水线触发局部退火，重构积分器为自适应步长 Runge-Kutta-Fehlberg 格式并拓宽求解域后平滑收敛；
- **过程 B（图表图例遮挡异常与自适应重构）**：发现内部图例框压盖了上升关键数据区，流水线强制废弃内部图例框，全面重构为**外置 Flex 胶囊图例条方案 B**，达成全图表数据零遮挡；
- **过程 C（公式未渲染与防死链自愈）**：彻底淘汰易受浏览器跨域拦截的外部 CDN 方案，改用 100% 离线内联 KaTeX 渲染引擎，结合双栏常驻预览窗格消除所有死链；
- **过程 D（TUN 模式网络拦截底层穿透）**：公网科学数据拉取遭遇系统虚拟网卡代理拦截（报非公网 IP 限制）时，底层网络适配器自动降级采用 Python 底层套接字直连穿透，杜绝静默失败与幻觉生成。

## 五、 出厂前 8 维质量防御门禁体系（`report_quality_check.py`）

本项目首创了科研智能体出厂前自动化质量门禁审查，在报告交付用户前强制执行 8 维刚性核验（0 容忍）：

1. **Check 1（元导语与自言自语拦截）**：拦截 `（原样引用）`、`不再临时引入新假设` 等自我标榜，保证行文客观严肃；
2. **Check 2（内部黑话清零）**：彻底清除正文可见 DOM 中的 `Node 0~4`、裸文件名 `problem_state.json`、`data_source_decision` 等内部词汇；
3. **Check 3（Markdown 语法完整渲染）**：杜绝裸 `#`、`>`、`|` 字符，确保所有标题、引用块与管道表格全部编译为语义化 HTML；
4. **Check 4（100% 离线 KaTeX 排版）**：公式离线自包含编译，彻底杜绝外部 CDN 请求，断网双击即可呈现出版级公式；
5. **Check 5（双栏常驻预览与零死链）**：提取正文全部 26 个 `data-artifact-key`，保证在载荷池中 1:1 对齐，无空 `href` 与失效路径；
6. **Check 6（分节过滤与三层程序下钻）**：程序按“程序 $\to$ 作用 $\to$ 迭代记录”展示调试历程；
7. **Check 7（纯中文说明规范）**：所有审计说明与运行记录采用规范简体中文，杜绝英文日志直接透传；
8. **Check 8（图表内联与图例零遮挡铁律）**：图表具备 `report-figure-inlined` 且曲线非水平死线，外置图例条保证数据零遮挡。
