## 一、 项目背景与问题需求

### 1. 技术背景与大语言模型在严谨科学计算中的常见问题
大语言模型本质上是基于概率预测下一个 token 的统计生成系统，在处理物理建模、航天动力学等严谨科学问题时，普遍面临以下客观困难：
1. **概率生成导致的物理幻觉**：模型缺乏底层的物理公理体系与符号量纲约束，若放任其直接输出推导或计算结果，容易产生量纲失配（如速度加加速度）、极端条件发散或不符合守恒定律的非物理现象；
2. **缺乏多步工具调用与验证闭环**：单轮问答难以支撑“任务解构 $\to$ 数据获取 $\to$ 控制方程推导 $\to$ 算法编写与积分 $\to$ 边界极端工况检验 $\to$ 异常回退 $\to$ 学术报告编排”的完整科研闭环；
3. **黑盒不可穿透、缺乏可审计性**：生成的数值结论缺乏透明的执行路径支撑，难以追溯到具体的参数输入、代码版本及执行日志；
4. **离线环境适应能力不足**：生成的报告若依赖外部在线 CDN，脱网或受限计算环境下公式与排版容易损坏；且跨机器部署时容易因缺少 Python 或科学计算包导致代码无法复现。

### 2. 项目目标与解决思路
针对上述问题，本项目基于 **Agnes Harness（AGH）** 设计了 **AI 物理科研工作站（Physics Research Agent）**。核心设计思想是**“由大语言模型负责逻辑推理与代码编写，由外部确定性工具链负责数值计算与严格质检”**，通过引入符号量纲门禁、极端退化边界门禁、嵌入式便携运行时、出厂前 8 维报告质检与离线双栏时序热跳转，实现无人工干预条件下的物理研究闭环，确保输出成果严谨、可验证、可审计。

## 二、 核心架构与方法论

### 1. 架构设计：非侵入式“1 路由 + 9 专业子 Skill”解耦治理体系
- **设计初衷与解决的问题**：若将全部物理科研规范写入一份庞大的单体 Skill 文档，会导致长会话中提示词过长、模型容易产生规则注意力分散；若直接改动 AGH 平台源码，则破坏了底座的纯净性与可移植性。
- **具体实现方案**：
  严格遵循 **AGH 零侵入扩展原则（Zero-Intrusion Baseline）**，不修改宿主平台任何源代码。在 `.agh/skills/` 建立了 **10 个职责明确的标准原生工作区技能（1 个 `physics-agent-orchestrator` 原生路由中心 + 9 个专业子 Skill）**，由 AGH 宿主自动扫描加载，并在不同阶段按需激活：

**10 大原生工作区技能的具体分工**：
1. `physics-agent-orchestrator`：顶层流程路由中心，识别物理题型并动态激活 6 节点流水线；
2. `physics-agent-governance`：全局主控协议，统筹物理隔离原则（§5）、产物独立存放规范（`<task-slug>/`）、工程红线与交付自检；
3. `physics-state-check`：任务隔离目录与 SSOT 状态账本（`problem_state.json`）生命周期纳管；
4. `physics-pipeline`：第一性原理任务解构、费米估算、最简基线优先与权威数据源分层决策；
5. `physics-defense-lines`：SymPy 量纲齐次门禁、边界退化极限门禁与局部退火控制；
6. `physics-auditability`：原子化执行留痕、SHA-256 散列签名与规范简体中文审计资产生成；
7. `physics-report-charting`：绘图规范、外置胶囊图例条（曲线数据零遮挡）、公式自包含内联；
8. `physics-report-writing`：八章学术论证结构、七条行文规范（杜绝内部黑话与行内元导语）；
9. `physics-permission-shortfall`：嵌入式便携运行时调度与权限/网络受限环境下的工程自愈；
10. `physics-doc-parsing`：外部科研论文、数据手册与专业图纸按需结构化解析。

### 2. 测试规范：纯净环境与物理隔离原则（§5 隔离原则）
- **设计初衷与解决的问题**：在自动化评估与比赛评审时，若智能体工作区残留有历史研发笔记、中间调试记录或参考答案，模型可能会直接读取并复用答案，导致无法客观评估其真实的解题与工具调用能力。
- **具体实现方案**：
  设立独立的 `ability-test7` 纯净测试规范。在该规范下，在文件系统层面彻底物理剥离所有的研发辅助文档与历史记录（即完全移除 `dev-notes/` 目录）；智能体在一个全新的、空白的会话中启动，仅依托原生注册的 10 个 Skills 完成题干解析、数据获取、代码编写、门禁拦截与报告生成。
- **带来的实际效果**：
  消除了工作区先验信息的干扰，确保测试过程完全基于模型自身的理解与工具调用，向评委证明了系统具备真实的解题泛化能力。

### 3. 环境保障：嵌入式便携运行时方案（Portable Runtime）
- **设计初衷与解决的问题**：实际评审或部署设备常常未安装 Python 3.10+ 环境，或缺少 NumPy、SciPy、SymPy、Pint 等重量级科学计算库，现场安装容易受网络波动与权限制约。
- **具体实现方案**：
  在 `physics-agent/third_party/portable-runtime/` 提供无安装器、不碰系统注册表的官方嵌入式 Python 3.13 运行环境，并预烘焙了版本锁定的依赖 wheels（`sympy==1.14.0`、`pint==0.26.1`、`numpy==2.5.3`、`scipy==1.18.1`、`matplotlib==3.11.2`、`plotly==7.1.0`）及 CJK 矢量字体。与 `physics-permission-shortfall` 技能协同，当环境检查发现系统缺少 Python 或必要依赖时，自动切换至便携运行时。
- **带来的实际效果**：
  保证了在脱网、无全局 Python 或受限沙箱环境中，所有物理门禁与求解脚本均能开箱即用稳定运行。

### 4. 连续执行六节点流水线（Pipeline）与规范路径归位
1. **Node 1（任务理解与第一性解构）**：提取研究对象、外场相互作用，提炼一句话核心目标；在写代码前先行执行**费米数量级估算**，为后续数值求解设立常识性物理参考范围；
2. **Node 1.5（公开数据源路由）**：按权威四级分类决策树选用数据（Level 0 本地库 $\to$ Level 1 官方 REST API $\to$ Level 2 权威静态备份 $\to$ Level 3 人机协同），针对本地代理虚拟网卡（TUN 模式）拦截自动采用 Python 底层套接字穿透，保证数据来源真实；
3. **Node 2a（机制匹配核验）**：对知识库方法模板进行逐行物理机制匹配检查，防范假设与题目场景不符；
4. **Node 2b（建模求解与四重物理工程防线）**：统一在任务专属目录 `physics-agent/runtime/<task-slug>/` 编写独立 Python 模型，执行量纲齐次性检验、极限退化边界检验、独立解析方法交叉核验与配额局部退火；
5. **Node 3（增量学术报告合成）**：按八章学术标准增量汇总至 `<task-slug>/report.md`，执行七条行文规范（零黑话、无行内元导语、公式 LaTeX 排版、管道表格、提炼主导规律与失效边界）；
6. **Node 4（双栏离线排版与热交互引擎）**：由 `trace_visualizer.py` 编译产出单文件离线 HTML，内置 Section 9（质量审计与自愈返工复盘）、三轨会话甘特图、蓝链毫秒级热跳转（Hot Jump）以及跨页零重载唤醒机制。

## 三、 三类运行工况与全链路验证证据链

为满足大赛对“正常情况、边界情况、失败情况”三类运行样例的严格验收要求，本项目以深空引力借力减速分析及历史真实走查记录提供全链路验证证据：

### 1. 正常工况（Normal Execution Case）
- **测试场景**：探测器以 $v_\infty = 20\ \text{km/s}$ 入射木星系，评估四颗伽利略卫星的单次飞掠最大减速量及推进剂节省比例；
- **执行过程与透明化调用**：
  - 智能体通过 Node 1 提炼一句话核心目标，先于数值代码执行**费米数量级估算**：预判木卫一公转速度约 $17\ \text{km/s}$，理论减速上限可达 $24\ \text{km/s}$，为后续求解设立常识性物理护栏；
  - Node 1.5 路由至权威公开常数源（$G_J = 1.2669\times10^8\ \text{km}^3/\text{s}^2$、木卫一至木卫四轨道半长轴），参数获取过程透明记录于账本；
  - Node 2a 经物理机制匹配核验，确认支配机制为无大气阻力影响的双体弹性动量交换，现场编写专属求解模型；
  - Node 2b 成功求解：
    - 木卫一（Io）单次飞掠最大减速 $\Delta v_{probe} = 24.51\ \text{km/s}$，对 $15.59\ \text{km/s}$ 入轨需求覆盖率达 $157.2\%$；
    - 化学燃料质量分数由 $98.93\%$ 降至 $0\%$（免化学动力直接捕获）；
  - 产出高分辨率矢量图表，采用外置 Flex 胶囊图例条，实现曲线数据无遮挡。
- **核验结论**：数值计算结果通过独立齐奥尔科夫斯基火箭方程交叉验证，吻合一致，每一次调用均生成 SHA-256 签名，过程完全留痕。

### 2. 边界与极端工况（Boundary & Degenerate Limits Case）
- **测试场景**：验证模型在物理极端或退化条件下的数学自洽性与物理退化行为；
- **边界探针设计（`boundary_spec.json`）**：
  1. **零引力退化极限**：令木星引力常数 $G_J \to 0$，卫星公转速度 $v_{moon} \to 0$。模型求解输出 $\Delta v_{probe} \to 0.0\ \text{km/s}$，自洽说明没有引力场时无法发生借力散射；
  2. **探测器质量无关性极限**：将卫星与探测器质量比放大 $10^6$ 倍。模型输出 $\Delta v_{probe} = 24.51\ \text{km/s}$ 严格保持恒定，符合双体弹性散射极限下减速量仅取决于卫星本底速度的物理结论；
  3. **渐近速度全域单调性扫描**：令入射速度在 $10 \sim 30\ \text{km/s}$ 范围内连续扫描，覆盖率单调平滑下降，无发散或非物理奇点。
- **核验结论**：边界门禁（`boundary_gate.py`）测试结果 100% PASS（3/3 探针全绿 + 扫描单调自洽），验证了模型在物理极值处的自洽性。

### 3. 失败、异常与自适应纠错工况（Failure & Error-Recovery Case）
在面对计算发散、排版冲突或网络阻断时，智能体通过四项主动自愈机制处理异常并如实记录：
- **过程 A（数值打靶截断异常与配额局部退火）**：初版打靶积分截断半径过小导致能量非物理跃迁（$\Delta E/E > 12\%$），边界门禁发出告警。状态机触发局部退火，重构积分器为自适应步长 Runge-Kutta-Fehlberg（RKF45）格式并拓宽求解域至 $10\times r_{Hill}$，平滑收敛消除警报；
- **过程 B（图表图例遮挡异常与自适应重构）**：排版扫描发现内部图例框压盖了上升关键数据区，重构为**外置 Flex 胶囊图例条（方案 B）**，消除图例遮挡；
- **过程 C（公式跨域拦截未渲染自愈）**：淘汰易受浏览器限制的外部 CDN 方案，改用 100% 离线自包含 KaTeX 预编译内联引擎，消除断网死链；
- **过程 D（TUN 模式网络拦截底层穿透）**：公网数据拉取遭遇系统虚拟网卡代理拦截（报非公网 IP 限制）时，底层网络接口自动降级采用 Python 底层套接字直连穿透，确保获取真实数据。

## 四、 任务泛用性扩展：高校物理教学推导与前沿探索双轨覆盖

为验证系统对不同类型物理命题的适应能力，本项目在架构上兼顾了**前沿科研探索**与**高校物理教学辅助**两类应用场景：

1. **前沿开放性科研探索**：
   - 外行星系统引力弹弓轨道规划、多星飞掠动量交换计算、多目标推进剂 Pareto 最优解搜索；
   - 弹道动力学仿真、非线性阻尼与多源摄动轨迹积分。
2. **大学物理课内多问标准推导教学场景**：
   - **光学波动与夫琅禾费衍射**：白光单缝衍射图样光强角分布计算、中央明纹半角宽度定量推导；
   - **瑞利判据与极限分辨本领**：推导圆孔衍射第一极小值角 $\theta \approx 1.22 \lambda / D$，建立仪器分辨本领模型；
   - **经典物理佯谬与常识量化检验**：例如针对“宇航员在 400 km 近地轨道能否仅凭肉眼分辨长城”，自主调取人眼瞳孔极限孔径（2~4 mm）与可见光波长（550 nm），推导出人眼极限角分辨率约 $3.36\times 10^{-4}\ \text{rad}$，对应地表最小可辨物宽约 134 米（长城墙基仅 5~8 米），通过定量计算分析该假说；
   - **阿贝显微镜极限分辨率**：基于数值孔径（$NA = n\sin\alpha$）计算浸没介质光瞳条件下的成像极限。
3. **复合多小问二级映射机制**：
   - 针对一题多问结构，状态机在 Node 1 自动构建多问拓扑树，在 Node 2b 逐题建立独立探针，并在 Node 3 映射为清晰的二级学术小节，避免结论混淆。

## 五、 Agnes Harness（AGH）的核心赋能作用与工程协同

本项目充分利用了 AGH 作为智能体执行底座的系统能力，实现平台工程与科学智能的结合：

| AGH 核心机制 | 在本项目中的具体赋能作用 | 对比传统无 Harness 脚本的实际效果 |
| :--- | :--- | :--- |
| **会话时序账本（`trace.jsonl`）** | 完整记录多轮次、近两百次工具调用的底层事件，带毫秒级时间戳与 SHA-256 签名。 | 记录真实的执行轨迹，为人工与机器复核提供不可篡改的依据。 |
| **持久化物理状态机（`problem_state.json`）** | 充当唯一事实源（SSOT），增量纳管假设层、控制方程、量纲表、数值解与异常池。 | 解决长上下文大模型遗忘关键参数的问题，支持长程复杂多步推导。 |
| **确定性安全审批与沙箱环境** | 拦截高危操作系统调用，提供受控的 Python 本地代码执行环境。 | 确保智能体在自动编写和执行数值脚本时处于安全受控状态。 |
| **便携运行时无缝对接** | 底座与 `physics-permission-shortfall` 协同调度嵌入式 Python 3.13 与预置 wheels。 | 解除对宿主机全局 Python 的依赖，提升了项目的即插即用性与环境鲁棒性。 |
| **双栏离线交互与热跳转 (Hot Jump)** | 报告内嵌三轨甘特图，支持正文蓝链与会话原始调用之间的毫秒级热跳转与脉冲高亮。 | 打通了学术报告正文与底层机器代码执行凭证之间的跳转查验路径。 |
| **跨页零重载唤醒 (BroadcastChannel)** | 通过轻量桥接参数和进程间通信，支持从 HTML 报告原地一键唤醒前台 AGH 会话标签页。 | 便于读者在查阅报告的同时直接定位原生会话，提升了人机交互体验。 |

## 六、 双重质量防御门禁体系（`report_quality_check.py` + `skill_bom_check.py`）

为确保最终交付成果的规范性，项目在成果交付前执行双重自动化检查：

### 1. 出厂前 8 维质量门禁自动化检测（`report_quality_check.py`）
1. **Check 1（元导语拦截）**：过滤提示词诱导的行内自我说明（如“题目（原样引用）：”、“不再临时引入新假设”等），保证行文客观严肃；
2. **Check 2（内部黑话清零）**：清除可见正文中的底层开发黑话（如 Node X）与裸文件名；
3. **Check 3（Markdown 语法完整渲染）**：校验所有标题、引用块与表格是否均已转为语义化 HTML；
4. **Check 4（100% 离线 KaTeX 排版）**：校验公式是否本地内联编译，无外部在线 CDN 请求；
5. **Check 5（双栏常驻预览与零死链）**：提取正文全部 `data-artifact-key`，保证在载荷池中 1:1 对齐，消除死链；
6. **Check 6（分节过滤与三层程序下钻）**：检查程序按“程序 $\to$ 作用 $\to$ 迭代记录”的三层结构完整性；
7. **Check 7（纯中文说明规范）**：确保所有审计说明与运行记录采用规范简体中文；
8. **Check 8（图表内联与图例零遮挡）**：校验图表内联呈现并满足外置图例条要求，防止数据曲线被压盖。

### 2. UTF-8 BOM 与 YAML frontmatter 合规门禁（`skill_bom_check.py`）
针对 Windows 平台下编辑器容易引入 UTF-8 BOM 导致宿主技能加载解析失败的问题，开发了专项目门禁工具，自动化检测并清除技能文件的 BOM 头，并核验 YAML 语法的合法性，保证技能加载稳定。
