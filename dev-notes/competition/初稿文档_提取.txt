Agnes AI Hackathon 项目结题报告

AI物理科研工作站（Physics Research Agent）

一、项目基本信息

1.1 项目名称

AI物理科研工作站（Physics Research Agent）

1.2 项目方向

科学计算与仿真 / 科研智能体（Agent）与 Harness 工程方向

1.3 项目定位

本项目基于 Agnes Harness（AGH）构建面向物理竞赛及科研分析场景的智能体系统。

项目目标并非简单实现 AI 问答，而是探索如何利用 Agent 技术辅助完成完整的物理问题分析流程，包括：

（1）物理问题理解；

（2）任务规划；

（3）数学模型建立；

（4）计算工具调用；

（5）结果验证；

（6）科研分析报告生成。

通过结合大语言模型的推理能力与专业计算工具，提高人工智能在科学计算场景中的可靠性、可解释性以及任务执行能力。

二、项目背景与问题来源

2.1 项目背景

在物理竞赛、工程计算以及科研分析过程中，一个完整的问题求解过程通常需要经历：

物理问题提出↓问题条件分析↓数学模型建立↓公式推导与参数分析↓数值计算↓结果验证↓形成科研报告

传统物理分析流程通常依赖人工完成，不仅需要较强的专业知识，同时存在以下问题：

（1）复杂问题建模过程耗时较长；

（2）计算过程容易出现人为错误；

（3）结果合理性需要额外验证；

（4）分析过程难以自动记录和复现。

近年来，大语言模型快速发展，在自然语言理解方面表现出较强能力，但直接应用于物理分析任务时仍存在一定不足：

（1）可能生成形式正确但物理意义错误的公式；

（2）缺少真实计算执行能力；

（3）缺少结果验证机制；

（4）难以形成完整科研工作流程。

因此，本项目希望利用 Agnes Harness 构建一个面向物理分析任务的智能 Agent，使 AI 从“回答问题”进一步发展为“执行任务”。

三、项目目标

本项目主要围绕以下目标展开。

3.1 构建物理问题分析流程

系统能够针对输入的物理问题，实现：

问题理解 → 任务规划 → 模型建立 → 工具调用 → 数值计算 → 结果分析 → 报告生成。

使 Agent 具备完整的问题处理流程。

3.2 提升 AI 计算结果可靠性

针对大模型可能产生的不准确推理结果，项目引入确定性验证机制。

主要包括：

（1）量纲一致性检查；

（2）数学表达检查；

（3）数值结果验证；

（4）物理规律合理性分析。

通过程序化方法辅助判断 AI 输出结果，提高计算过程可靠性。

3.3 建立可追踪的 Agent 执行流程

系统记录：

（1）用户输入信息；

（2）任务规划过程；

（3）工具调用过程；

（4）计算结果；

（5）验证结果。

形成完整的执行链路，为后续测试、调试以及比赛验收提供依据。

四、系统总体设计方案

4.1 系统整体架构

本项目整体架构主要包括四个部分：

（1）AGH Agent 执行层

负责：

接收用户任务；

理解问题需求；

制定执行计划；

调度计算工具；

管理任务状态。

（2）物理分析模块

负责：

提取关键变量；

分析物理条件；

建立数学模型；

生成计算方案。

（3）计算工具模块

负责：

执行数值计算；

处理实验数据；

生成可视化结果。

（4）结果验证模块

负责：

检查计算结果；

判断物理合理性；

反馈异常情况。

五、核心技术实现

5.1 Agent任务执行流程

系统整体执行流程如下：

第一步：任务输入

用户输入物理问题，Agent 对问题进行分析。

第二步：任务理解

提取：

已知条件；

求解目标；

相关参数。

第三步：任务规划

根据问题特点制定：

建模方案；

计算步骤；

所需工具。

第四步：工具调用

调用计算工具完成：

数值计算；

数据处理；

图像生成。

第五步：结果验证

对计算结果进行检查。

第六步：报告生成

输出完整分析结果。

5.2 量纲验证机制

为了降低 AI 在物理公式推理过程中产生错误的风险，本项目设计了量纲验证模块。

该模块主要用于：

（1）检查公式单位是否满足物理规律；

（2）发现潜在公式错误；

（3）辅助判断模型建立是否合理。

实现过程中，通过引入成熟科学计算工具，对物理量单位和数学表达进行解析，实现自动化辅助检查。

量纲验证流程如下：

物理公式输入↓单位解析↓量纲计算↓一致性判断↓输出验证结果

5.3 数值计算与可视化能力

项目通过 Python 科学计算环境，实现：

（1）数值计算；

（2）参数分析；

（3）数据处理；

（4）科学绘图。

同时开发了面向科研分析场景的数据可视化能力，包括：

曲线图；

散点图；

热力图；

数据关系展示。

通过可视化结果帮助用户理解计算过程和分析结果。

5.4 执行过程记录机制

为了保证 Agent 执行过程可追踪，系统记录：

（1）输入信息；

（2）任务执行步骤；

（3）工具调用情况；

（4）计算结果；

（5）异常信息。

执行记录能够帮助开发人员分析系统行为，同时为比赛验收提供过程证明。

六、项目开发过程总结

6.1 第一阶段：需求分析与架构设计

项目初期围绕比赛要求进行分析，确定项目不能仅依赖 Prompt，而需要构建完整 Agent 执行流程。

最终确定技术路线：

问题理解 → Agent规划 → 工具调用 → 结果验证 → 报告生成。

6.2 第二阶段：核心功能开发

主要完成：

（1）物理问题分析流程设计；

（2）工具调用机制建设；

（3）量纲验证模块设计；

（4）数据可视化功能开发；

（5）执行过程记录能力建设。

6.3 第三阶段：测试优化

在测试过程中发现并解决多个问题。

问题一：流程控制不足

解决方案：

优化任务执行流程，加强状态管理。

问题二：部分物理量解析不足

解决方案：

完善物理量映射和解析逻辑。

问题三：外部数据访问受到环境限制

解决方案：

调整数据获取策略，优先使用符合比赛环境要求的数据来源。

七、项目测试与验证

为验证系统稳定性，项目进行了多类型测试。

7.1 正常测试

测试内容：

输入标准物理问题，验证系统是否能够完成：

问题理解 → 工具调用 → 计算分析 → 结果输出。

7.2 边界测试

测试内容：

针对特殊参数和复杂输入情况，验证系统是否能够保持合理运行。

7.3 异常测试

测试内容：

模拟：

（1）工具调用失败；

（2）数据不足；

（3）输入条件不完整。

验证系统是否能够：

识别异常；

停止错误流程；

返回合理提示。

九、项目创新点

9.1 从问答式 AI 转向执行式 AI

传统 AI 更多关注生成答案。

本项目关注 AI 是否能够真正完成任务，通过 Agent 机制实现连续执行。

9.2 AI推理能力与确定性计算结合

通过：

大语言模型推理能力

专业计算工具

结果验证机制

提高科学计算任务可靠性。

9.3 强调过程可追踪

项目不仅关注最终结果，同时记录：

执行过程；

工具调用；

验证结果。

提高系统透明度。

十、项目不足与未来优化方向

10.1 复杂物理领域覆盖不足

目前系统主要面向典型物理分析任务。

未来将进一步扩展：

更多物理领域模型；

更多专业计算能力。

10.2 自动建模能力仍需提升

当前建模过程仍依赖大模型能力。

未来计划：

增加领域知识库和模型模板，提高自动建模能力。

10.3 数据管理能力需要完善

未来将进一步优化：

数据管理机制；

数据调用策略；

数据验证流程。

十一、总结

本项目基于 Agnes Harness 构建了 AI 物理科研工作站。

通过 Agent 任务规划、工具调用、科学计算以及结果验证，实现了面向物理问题分析任务的完整智能执行流程。

项目探索了人工智能 Agent 在科学计算领域中的应用方式，使 AI 不仅能够进行文本交互，同时能够参与真实科研分析过程。

未来，本系统将在更多工程计算、科研辅助以及教育实验场景中进行进一步探索。
