## 详细设计解析（问题背景、实现方案与实际效果）

### 一、 非侵入式“1 路由 + 9 专业子 Skill”解耦架构

1. **源于什么问题 / 出于什么需求**：
   在基于 Agent Harness 构建垂直领域智能体时，常见做法是编写一个长达数万字的单体规则文档（如超长 SKILL.md），或直接改动 AGH 平台的底层代码。这种做法导致：
   - 模型在单次会话中载入过多不相关指令，容易引起指令注意力分散或遗忘；
   - 调试与维护成本高，修改某一环节的逻辑容易牵一发而动全身；
   - 破坏了宿主平台的纯净性，难以在其他 AGH 标准环境中平滑迁移。

2. **对应设计方案与技术实现**：
   - **底座零侵入**：严格基于 AGH 原生提供的标准 Tool 与 Skill 接口，不改动宿主平台任何源代码；
   - **模块化解耦**：将物理研究的全生命周期拆解为 10 个功能明确的工作区技能（位于 `.agh/skills/`）：
     - `physics-agent-orchestrator`（流程路由调度）；
     - `physics-agent-governance`（全局规范与红线治理）；
     - `physics-state-check`（任务隔离与状态机维护）；
     - `physics-pipeline`（第一性原理任务拆解与数据源选择）；
     - `physics-defense-lines`（量纲与边界极值门禁）；
     - `physics-auditability`（时序留痕与审计存证）；
     - `physics-report-charting`（出版级绘图与内联呈现）；
     - `physics-report-writing`（八章学术报告结构与文风约束）；
     - `physics-permission-shortfall`（便携运行时与受限环境兜底）；
     - `physics-doc-parsing`（外部文献与图纸结构化解析）。
   - **动态按需激活**：由路由器 Skill 依据当前题型与所处阶段，提示并引导模型按需读取对应子技能，避免无关规则挤占注意力。

3. **带来的实际效果**：
   - 保持了 AGH 宿主底座的原生纯净性，便于跨平台无缝分发；
   - 每一个子技能职责单一清晰，上下文利用率显著提升，降低了长长程交互中的偏航概率。

### 二、 纯净环境与 §5 物理隔离原则

1. **源于什么问题 / 出于什么需求**：
   在自动化测试或比赛评审中，大模型若在工作区内直接访问历史会话记录、中间调试草稿或预先整理好的参考答案，容易直接复用已有答案生成结果，形成“伪推理”与“虚假泛化”。这种情况下，评委无法判断模型是真正具备物理分析与代码闭环能力，还是仅仅读取了现成文件。

2. **对应设计方案与技术实现**：
   - 制定了 `ability-test7` 纯净测试规范：在进入测试验证前，在文件系统层面彻底物理剥离所有的研发辅助文档与历史记录（即完全移除 `dev-notes/` 目录）；
   - 在全新的、空白的 AGH 会话中冷启动，工作区仅保留平台底座、10 个原生技能定义以及通用的物理计算工具脚本；
   - 题干作为全新输入提交，要求智能体从零开始执行解题流程。

3. **带来的实际效果**：
   - 排除了工作区先验信息的干扰，向评审专家证实了模型每一次推理、代码编写与门禁调用的真实性与独立性；
   - 验证了系统的工具调用能力与算法流程具有真正的泛用性，而非依赖预置文件。

### 三、 四重确定性物理工程硬防线

1. **源于什么问题 / 出于什么需求**：
   纯文本大语言模型的核心机制是基于上下文词元概率预测下一个 token，并不具备底层的数学计算引擎与物理公理系统。如果放任模型直接口算物理量或凭直觉编写数值脚本，极易出现量纲混淆、不满足守恒定律、极端条件下发散等物理幻觉问题。

2. **对应设计方案与技术实现**：
   确立“不使用模型口算物理量”的原则，由模型编写形式化代码，交由外部确定性工具严格检验，构建四道刚性防线：
   - **防线 1：符号量纲齐次性门禁（`dimensional_gate.py`）**：调用 SymPy 建立待测物理方程的符号语法树，利用 Pint 物理单位库校验等式两端基本量纲向量是否严格一致（如速度两端必须为 $[length]/[time]$），若量纲不匹配则直接阻断执行；
   - **防线 2：物理退化极限与单调性扫描门禁（`boundary_gate.py`）**：在 `boundary_spec.json` 中配置极端工况探针。例如令外场引力参数趋于零时，减速量必须自洽趋于零；将质量比增大数个数量级时，两体弹性散射极值必须保持恒定；对入射速度进行单调性扫描，检验数值曲线是否平滑收敛；
   - **防线 3：独立正交解析理论交叉核验**：除主数值求解器外，必须引入不相关的独立解析公式（如齐奥尔科夫斯基火箭方程）对关键结果进行验算比对；
   - **防线 4：状态账本与时序机器存证（`audit_log.py`）**：将任务所有参数、假设与结果纳管在 `problem_state.json` 唯一事实源中，所有外部脚本执行均记录精确时间戳与 SHA-256 散列签名。

3. **带来的实际效果**：
   - 在模型代码执行与成果收口的关键节点设立了机器可检验的硬指标，防止低级物理错误被带入最终结论；
   - 保证了数值模型在边界工况与物理极限下的数学自洽性。

### 四、 拒绝妥协的真机求解三大自愈闭环

1. **源于什么问题 / 出于什么需求**：
   在自动化执行与真实科学计算过程中，常常会遇到因模型初版公式理解颠倒导致的非物理结果、边界规范路径不匹配引发的模块导入报错、或本地虚拟网卡代理触发的网络误报等真实异常。传统 Agent 面对此类问题通常直接崩溃中断，或者为了强行继续而在后续步骤人工拼凑伪造数据。

2. **对应设计方案与技术实现**：
   在状态机与流水线中建立了真机运行时的异常捕获与局部自愈闭环（与交付报告 Section 9.3 1:1 对齐）：
   - **闭环 1（核心物理数值层自愈）**：
     - *触发诱因*：初版求解脚本误将消除相对超速差值定义为相反方向（$\Delta v_{req} = v_\infty - v_{capture} = -15.594\ \text{km/s}$），代入齐奥尔科夫斯基推进剂方程计算得出非物理的负燃料质量分数（`frac_chem = -9284%`）；
     - *拦截机制*：独立交叉核验逻辑检测到违反质量守恒基本公理，当场阻断数据签入，记入状态机异常账本；
     - *自愈纠偏*：AI 深度推理定位到符号差值定义颠倒，调用 `edit` 工具定向修补表达式为正向差值；
     - *最终核验*：第 2 次运行完全收敛，木卫一覆盖率 157.2%，燃料消耗削减至 0%，独立交叉验证完全吻合。
   - **闭环 2（物理边界极值层自愈）**：
     - *触发诱因*：初版编写 `boundary_spec.json` 时长模块路径不匹配，导致边界门打靶时抛出导入报错（退出码非 0）；
     - *拦截机制*：物理边界门发出阻断告警，禁止未检验模型进入报告阶段；
     - *自愈纠偏*：AI 捕获错误日志，调用 `edit` 工具将 `model_module` 修正为标准平铺模块名 `gravity_assist_model`；
     - *最终核验*：重新运行边界门，3/3 项极限检验与单调性扫描全部达到 PASS。
   - **闭环 3（科学数据获取层自愈）**：
     - *触发诱因*：Node 1.5 检索公开发表天文常数时，宿主机本地代理虚拟网卡（TUN 模式）导致域名解析至假公网段（`198.18.x.x`），触发 SSRF 防护阻断；
     - *拦截机制*：AI 识别报错属于本地网络代理环境冲突而非数据不存在，拒绝伪造假数据；
     - *自愈纠偏*：自动降级为轻量 Python 脚本调用系统底层网络套接字（Socket）直连穿透；
     - *最终核验*：成功拉取官方标准常数并完整签入状态账本。

3. **带来的实际效果**：
   - 证明了系统在面对真实的计算发散、路径错误与网络受限时具备自主容错与自愈纠偏能力；
   - 确保了所有修复过程均有迹可循，杜绝了下游私自修改数据来掩盖上游缺陷的现象。

### 五、 嵌入式便携运行时工程方案（Portable Runtime）

1. **源于什么问题 / 出于什么需求**：
   在实际的比赛现场、评委本地电脑或受限计算环境中，往往面临机器上未安装 Python 3.10+、没有管理员权限、或依赖包安装受限等实际困难。若要求评审人员手动配置复杂的科学计算环境，极易因网络或版本差异导致项目无法复现。

2. **对应设计方案与技术实现**：
   - 在 `physics-agent/third_party/portable-runtime/` 随包提供了免安装、不修改系统环境变量与注册表的官方嵌入式 Python 3.13 运行环境；
   - 预先下载并内置了项目所需的锁定版本 wheel 文件，涵盖 `sympy==1.14.0`、`pint==0.26.1`、`numpy==2.5.3`、`scipy==1.18.1`、`matplotlib==3.11.2`、`plotly==7.1.0`；
   - 附带了 CJK 矢量字体资产，避免在缺少中文字体的纯英文操作系统中绘制矢量图表时中文显示为方块；
   - 与 `physics-permission-shortfall` 技能协同，当环境检查发现系统缺少 Python 或必要依赖时，系统能够自主切换至便携运行时。

3. **带来的实际效果**：
   - 评委或新用户无需预先配置 Python 环境，脱网状态下即可直接双击运行并验证全部核心门禁脚本；
   - 实现了项目运行环境的确定性锁定，消除了因环境版本漂移带来的复现偏差。

### 六、 离线双栏交互、自由缩放与甘特热跳转（Hot Jump）

1. **源于什么问题 / 出于什么需求**：
   - 传统大模型生成的文本报告往往与底层的机器执行记录脱节，读者很难核实报告正文中的具体数字究竟出自哪一次脚本运行或哪一行代码；
   - 在脱网或涉密环境中，依赖外部在线 CDN 渲染的 HTML 报告容易出现公式源码裸露、样式丢失与死链问题；
   - 用户在查阅交付的 HTML 报告时，固定宽度的侧边栏容易在不同屏幕分辨率下产生视觉挤压，且单行长日志经常被右侧边缘截断，影响审查效率。

2. **对应设计方案与技术实现**：
   - **完全离线自包含**：单文件 HTML 格式，内联样式与 KaTeX 字体规则，脱网打开时公式与矢量图均能完整展现；
   - **矢量图表外置胶囊图例条**：图表采用标准矢量 SVG，图例移至绘图区域外侧的独立 Flex 胶囊条中，实现物理数据曲线 100% 零遮挡；
   - **右侧常驻资产窗格支持自由拖拽缩放**：左边缘提供专用拖动手柄，支持在 340px 至 1100px+ 之间平滑无级拉伸宽度，并提供四档快速预设（480px / 640px / 800px / 50% 均分），自适应宽屏显示器；
   - **Trace 消息自动换行切换**：消息窗口顶部提供【自动换行 / 保持单行】切换按钮，长命令与多行输出可完整展开查验；
   - **离线三轨会话甘特图**：在离线 HTML 内部复刻了 AGH 会话轨迹，分为用户输入轨、模型推理轨与工具执行轨，直观展示两百次调用的耗时与前后时序；
   - **正文蓝链热跳转（Hot Jump）**：点击报告正文中的关键程序或数据链接，右侧轨迹列表即时平滑滚动居中并高亮该卡片，甘特图对应时间块同步联动；
   - **跨标签页零重载唤醒（BroadcastChannel）**：在报告中点击返回 AGH 查看按钮，通过轻量桥接参数和浏览器进程间通信，已打开的 AGH 页面无需刷新即可原地切换到对应轨迹项。

3. **带来的实际效果**：
   - 实现了交付学术成果与底层机器执行凭据的无缝互查，使每一次工具调用的输入、输出和耗时都透明可核验；
   - 提供了灵活从容的阅读与审查视野，保证了在完全断网条件下报告依然具备完整的排版展示与交互功能。

### 七、 出厂前 8 维质量门禁与 BOM 拦截体系

1. **源于什么问题 / 出于什么需求**：
   大语言模型在生成 Markdown 或 HTML 报告时，受提示词历史或模式生成影响，容易在正文中残留无意义的行内自我说明（如“题目（原样引用）：”、“正文里用编号引用不再引入新假设”等元话语），或将底层的流程节点号、内部 JSON 字段名直接暴露给读者。此外，Windows 编辑器常自动引入 UTF-8 BOM 头，可能导致宿主技能加载解析失败。

2. **对应设计方案与技术实现**：
   - **`report_quality_check.py` 自动化质检脚本**：在最终报告生成后、交付用户前，对 HTML 结构执行 8 维刚性扫描：
     1. 拦截行内元导语与自言自语（黑名单过滤）；
     2. 清除可见正文中的底层开发黑话与裸字段名；
     3. 校验 Markdown 标题、表格、引用块是否已全部编译为语义化 HTML；
     4. 校验公式是否已完成本地内联渲染，且无外部网络请求；
     5. 提取全部 `data-artifact-key`，校验是否与载荷池中的数据 1:1 对齐，消除死链；
     6. 校验代码呈现的三层结构完整性；
     7. 检查审计说明文字是否全部规范转化为简体中文；
     8. 校验图表是否内联且具备外置图例条。
   - **`skill_bom_check.py` 合规工具**：对工作区全部技能文件进行 UTF-8 BOM 扫描，自动清除多余 BOM 字符并核验 YAML frontmatter 合法性。

3. **带来的实际效果**：
   - 将报告的质量审核从人工经验检查转变为确定性的程序化质检，杜绝了低级排版与语病遗留；
   - 保证了交付给读者的学术报告行文规范、严肃，符合正式科研成果的标准要求。

### 八、 任务泛用性扩展：课内多问推导与前沿探索双轨覆盖

1. **源于什么问题 / 出于什么需求**：
   在实际的科研与教学应用中，物理问题既有面向未知参数空间的大规模数值模拟与多目标权衡（如深空轨道规划），也有具备严密解析理论体系、标准答案及复合多问结构的基础教学问题（如波动光学推导、物理假说验证）。单一的解题逻辑难以兼顾这两类不同的任务特征。

2. **对应设计方案与技术实现**：
   - **复合多小问拓扑解构**：在 Node 1 遇到一题多问题目时，自动解析题目依赖关系并建立多问拓扑树；
   - **独立探针求解与分节映射**：在 Node 2b 针对各小问设立相互解耦的求解探针，并在 Node 3 映射为清晰的二级学术小节，避免上下文串扰；
   - **覆盖多领域权威物理模型**：在知识库中储备了轨道动力学、几何与波动光学、经典流体力学等不同领域的基础方程与验证方法。

3. **带来的实际效果**：
   - 验证了工作站不仅能解决复杂的深空轨道数值优化赛题，同样能准确完成大学物理课内多小问的严密理论推导（如单缝衍射分布、仪器分辨率极限、宇航员近地肉眼看长城假说定量证伪等）；
   - 证明了整套六节点流程具有良好的领域适应性与任务泛用性。
