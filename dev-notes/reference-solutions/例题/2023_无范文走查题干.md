# 无范文走查：贴入新会话的题干（仅 2023 题原始题干，不含范文任何分析/建模/结论）

## 走查操作

把下面两段**依次**贴进一个全新 Agnes 会话（第 1 段必须先发，第 2 段紧接着发，模拟真实演示开场）：

**第 1 段（开场指令，模拟真实用户对 agent 说的第一句话）：**
```
请使用 physics-agent-governance skill 处理下面这道物理题。
```

**第 2 段（纯净题干，3 行，赛事原题，无任何范文分析痕迹）：**
```
**Problem A: Space Diving**

Consider a skydiver, carried by a rocket vertically up to an altitude, perhaps
above the Earth's atmosphere, who then exits the rocket in a space suit with
a parachute, to descend back down to the Earth's surface. Analyze the
challenges and dangers in such a descent, assuming that the total mass of the
skydiver, space suit, and parachute is 190 kg. What would be the maximum
altitude from which a person could successfully descend to the surface?
```

> 说明：之所以必须发第 1 段，是因为 AGH 的 Skill 机制是"只有名字被显式
> 提及才会自动预加载 SKILL.md 正文"（已查证过的宿主机制事实，不是本次
> 走查要验证的假设）。缺了这一句开场指令，新 agent 根本看不到我们的协议，
> 会直接凭 LLM 直觉自由发挥，走查结果会全是红叉——但红叉原因是
> "Skill 没被加载"，不是"协议写不清楚"，会得出错误结论。

## 走查判据（不依赖任何范文数值，纯物理/协议判据）

走查完成后，按下面这份清单打勾，不跟范文具体数值做比对：

- [ ] **Node 1**：agent 是否把题目规约成一份 `problem_state.json`（用
      `problem_state_template.json` 起的新实例），而不是直接跳去建模？
- [ ] **Node 1.5**：agent 是否主动判断"这道题需要什么外部数据"（比如
      大气密度/温度随高度变化），并给出"用什么数据源、为什么"的
      判断+理由，而不是直接写死一个数据源名字？
- [ ] **数据源判断**：agent 判断出的候选数据源是否合理（比如标准大气
      模型/数值大气模型这类**类型**，不要求它精确说出"ambiance"或
      "pymsis"这两个库名——如果它判断成"应该查一个 0–80 km 标准大气
      + 80–150 km 数值大气模型的组合"这类层次，说明数据源路由模板真正
      起作用了，不需要它恰好报出我们开发时用的那两个库名）？
- [ ] **Node 2a**：agent 是否路由到一份方法论模板，并对该模板做
      "是否需要改编"的判断（比如"这道题有没有需要新增/修改模板里
      某一步"），而不是把模板七步原样照搬？
- [ ] **Node 2b 建模**：agent 建出的 ODE 是否通过了 `dimensional_gate.py`
      的量纲检查（如果它实际调用了这个钩子）？
- [ ] **结果自检（不依赖范文）**：agent 是否做了至少一项**不依赖任何
      具体范文数值**的验证？候选判据包括：
    - CD → 0 时模型是否退化为"接近自由落体"（纯重力加速度 ≈ g）
    - 质量 → ∞ 时加速度是否趋近 g（阻力项被大质量摊薄）
    - 初始高度 → 0 时最大速度是否趋近 0
    - 这些极限行为是否物理上说得通，比"算出的最大速度/最大过载跟
      某个范文对得上"更有诊断价值
- [ ] **失败/边界情况**：走查过程中 agent 是否遇到了任何"判断不下去"
      的环节（比如某类数据源检索不到），并按 `data-source-routing.md`
      的 Step 5a 生成过"选项 A/选项 B"提示，而不是直接卡死或瞎编数据？
- [ ] **参考资料隔离**（§5 条款核对）：agent 是否在 `audit_logs`/`anomalies`
      里留下过**任何一次** `dev-notes/` 相关文件的引用记录？（包括"拒绝引用"
      的留痕也算，需要逐条核实）——判据不是凭 agent 自我声明"我没看"，而是
      去实际翻它本次 run 的 `problem_state.json` 的 `audit_logs` 字段，确认没有
      一条记录写着"参考了 dev-notes/…"；同时对照会话 trace 里的工具调用记录，
      确认没有对 `dev-notes/` 下任何路径执行过 read/grep 类操作

## 走查本身不要求的东西（明确列出，避免误判）

- 不要求 agent 算出的数值接近 2023 范文的 467.7 m/s / 9.68 m/s²
  / 94 km / 80 km 这些**范文作者自己算出的结果**——这些数字是那个
  特定团队特定假设下的输出，不是题目本身的"标准答案"，走查用它们
  做对照本身就是之前明确要剔除的"依赖范文"漏洞。
- 不要求 agent 恰好选到 `ambiance` + `pymsis` 这两个具体库名——
  这两个库名是**我们开发时选定的**实现细节，属于开发侧知识，
  走查只关心"它有没有按 Level 0（本地可验证的库）优先的判断逻辑
  去检索/判断数据源"这个**方法论**是否被真正执行，不关心它是不是
  恰好选到跟我们一样的库。
