# AI 物理科研工作站安装与快速入门指引

本文档面向从 GitHub Release 下载预编译包或克隆本项目的用户，介绍如何在本地计算机上完成环境自检、依赖配置、服务启动以及常见问题的排查。

## 一、 系统环境要求

| 组件 | 推荐配置 / 最低要求 | 说明 |
| :--- | :--- | :--- |
| **操作系统** | Windows 10 / 11 (x64)<br>macOS 12+ (Apple Silicon / Intel)<br>Linux (Ubuntu 20.04+ / Debian 11+) | 提供 Windows 原生批处理脚本与全平台通用命令。 |
| **系统架构** | 64 位操作系统 (x64 / arm64) | 科学计算与数值积分需要 64 位支持。 |
| **Node.js** | `>= 24.10`（推荐使用 Node.js 24 LTS） | Agnes Harness 底座运行环境。 |
| **包管理器** | `pnpm >= 10.0` | 项目依赖包管理工具。 |
| **Python** | Python 3.10+ | 用于执行物理数值求解、量纲检验与矢量图表绘制。<br>*（若未安装，系统支持调用内置的便携式 Python 运行时）* |
| **硬件要求** | 双核 CPU，4 GB 可用内存，2 GB 可用硬盘空间 | 无需独立 GPU，物理求解与绘图均为轻量 CPU 高精度算法。 |

## 三、 方式一：Windows 全量预构建发行包安装流程（推荐）

对于未配置复杂开发环境的 Windows 10 / 11 纯净计算机，推荐直接下载预构建发行包体验完整功能：

### 1. 下载与解压
在 GitHub Releases 页面下载 **`AI_Physics_Agent_v1.0.0_Windows_x64.zip`**，解压到任意磁盘目录（例如 `D:\AIPhysicsAgent` 或桌面）。

### 2. 运行图形化安装向导
进入解压后的文件夹，双击运行 **`图形化安装.bat`**（或直接运行 `installer\AI_Physics_Agent_Setup.exe`）：
- **步骤一：环境自检与依赖自动补全**：
  - 界面实时显示 64 位系统架构、Node.js、pnpm、Python 科学环境以及内置离线便携包的状态；
  - **Node.js 自动配置（小白免配置）**：若检测到系统未安装 Node.js，向导会自动勾选下载选项，安装时优先调用 `winget`，若无 `winget` 则自动从官方镜像静默拉取 Node.js 24 LTS 官方安装包完成部署；
  - **Python 科学库自动配置**：若检测到缺少 SymPy、Pint、NumPy、SciPy、Matplotlib，向导自动调用 pip 补齐，若完全无 Python 亦支持调用官方静默安装器；
- **步骤二：选择主程序安装位置与运行模式**：
  - 自由选择主安装目录，界面实时核算所需磁盘空间与目标盘剩余空间；
  - **选择环境隔离模式**：支持单选“独立物理科研环境 (4180)”、“虚拟沙箱隔离环境 (4182)”或“接入系统默认环境 (4177)”，自带端口占用检测；
- **步骤三：自动化部署与正规系统注册**：
  - 向导自动部署核心代码，因预编译包已内含构建产物，**无需本地安装 Visual Studio 或执行 C++ 编译，秒级完成部署**；
  - 自动生成带有专属高分辨率图标（`app.ico`）的桌面快捷方式与开始菜单程序组；
  - 正规注册至 Windows 注册表 `Software\Microsoft\Windows\CurrentVersion\Uninstall\AIPhysicsAgent`，使软件正规出现在 Windows **“设置 ➔ 应用 ➔ 已安装的应用”** 及 **“控制面板 ➔ 程序和功能”** 列表中；
- **步骤四：一键启动**：
  - 安装完成后，勾选“立即启动”，点击完成即可自动拉起服务并在浏览器中打开工作台。

## 四、 系统的正规卸载与数据保护机制

若您未来需要从计算机中移除本系统，可以通过以下正规途径进行一键完整卸载：
1. **途径 A**：打开 Windows **“设置 ➔ 应用 ➔ 已安装的应用”**（或控制面板），找到 **“AI 物理科研工作站 (Physics Research Agent)”**，点击 **“卸载”**；
2. **途径 B**：点击 Windows 开始菜单 ➔ **“AI 物理科研工作站”** 程序组 ➔ 点击 **“卸载 AI 物理科研工作站”**；
3. **途径 C**：直接进入主安装目录，双击运行 **`Uninstall.exe`**。

> **核心数据安全保护**：  
> 卸载程序启动时，会弹出确认窗口，并默认勾选 **“保留工作区中用户自建的物理研究成果与历史报告 (agh-workspace/)”**。这确保了在彻底清除程序文件、注册表项与桌面快捷方式的同时，**绝对不会误删您自己生成的物理仿真数据与学术报告**。若您希望彻底清除所有数据，只需取消勾选即可。

## 五、 方式二：双击批处理一键脚本安装

如果您习惯直接通过轻量批处理运行，也可以使用预置的脚本方案：

### 第一步：环境检查与一键安装
双击运行项目根目录下的 **`一键安装.bat`**。  
*脚本将按顺序自动完成：*
1. 检测 Node.js 与 pnpm 状态（若未安装 pnpm，将自动尝试通过 Corepack 启用）；
2. 自动安装项目底座依赖包（`pnpm install`）；
3. 检查系统 Python 与核心科学计算库（SymPy、Pint、NumPy、SciPy、Matplotlib）；
4. 编译本地命令行与底座服务模块。

### 第二步：一键启动服务
安装成功后，双击运行根目录下的 **`一键启动.bat`**。  
*程序启动后将：*
1. 自动同步物理技能与分析工具到工作区；
2. 释放并监听本地端口（默认端口为 `4180`）；
3. 自动调出默认浏览器打开工作台前台：`http://127.0.0.1:4180`。

> **日常自检提示**：任何时候若遇到运行异常，可直接双击运行根目录下的 **`环境自检.bat`**，系统会以表格形式输出当前 Node.js、pnpm、Python 及各科学库的可用状态，并附带针对性的解决建议。

## 六、 方式三：跨平台与终端手动安装指南（macOS / Linux / 通用终端）

如果您习惯使用命令行，或在 macOS / Linux 系统下运行，请在终端中执行以下标准流程：

### 1. 克隆代码并进入目录
```bash
git clone https://github.com/VirtuwiseZ/agnes-harness.git
cd agnes-harness
```

### 2. 执行环境诊断（可选）
在 PowerShell 中执行：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/doctor.ps1
```

### 3. 安装依赖与本地编译
```bash
# 启用 pnpm（若未安装）
corepack enable
corepack prepare pnpm@10.34.5 --activate

# 安装底座依赖
pnpm install

# 本地构建 CLI 模块
pnpm --filter @agnes/cli run build:local
```

### 4. 安装 Python 核心科学计算库
```bash
pip install -r physics-agent/hooks/requirements.txt
```
*所需依赖清单：*
- `sympy>=1.12`：符号数学代数与量纲解析
- `pint>=0.23`：物理单位制与量纲齐次性自动核验
- `numpy>=1.26`：多维数组、空间网格与离散差分
- `scipy>=1.12`：变步长常微分方程积分（`solve_ivp`）与特殊函数
- `matplotlib>=3.8`：出版级矢量图表绘制引擎

### 5. 启动服务
```bash
# 启动后台守护服务（指定端口 4180）
node packages/cli/dist/local/agnes.mjs daemon start --port 4180
```
启动完成后，在浏览器中访问：`http://127.0.0.1:4180`。

## 四、 常见依赖缺失的处理指引

### 1. 系统未安装 Node.js 或版本过低
- **现象**：运行脚本时提示 `未检测到 Node.js，无法继续安装` 或版本低于 `24.10`；
- **解决方式**：
  1. 访问 Node.js 官方网站：[https://nodejs.org/](https://nodejs.org/)；
  2. 下载并安装当前最新的 **Node.js 24 LTS** 或最新版本；
  3. 安装完成后重启终端即可。

### 2. 未检测到 pnpm 包管理器
- **现象**：终端提示 `pnpm: command not found`；
- **解决方式**：
  - 如果使用的是 Node.js 24，官方已内置 Corepack，直接在终端执行：
    ```bash
    corepack enable
    corepack prepare pnpm@10.34.5 --activate
    ```
  - 或者通过 npm 进行全局安装：
    ```bash
    npm install -g pnpm@10.34.5
    ```

### 3. 系统未安装 Python 或缺少科学计算库
- **方案 A（联网安装）**：直接在系统终端中执行：
  ```bash
  pip install sympy pint numpy scipy matplotlib
  ```
- **方案 B（脱网环境便携运行时兜底）**：  
  如果所处环境无法联网或无管理员权限，项目在 `physics-agent/third_party/portable-runtime/` 提供了免安装的官方嵌入式 Python 3.13 依赖配置与预烘焙 wheels。系统检测到缺少全局 Python 库时，会自动调度便携运行时与离线 wheels 包进行计算，无需手动安装。

## 五、 多环境多端口并行与会话数据完全隔离机制（高阶稳健性）

在严谨的科研实验或团队协作中，用户常需要在同一台计算机上运行不同的研究任务，甚至与已有的通用 AGH 实例共存。本项目严格遵循官方《配置参考》与《会话与恢复指南》，实现了**多环境多端口并行、不同网页主页与会话记录彻底物理隔离**的稳健运行架构：

### 1. 官方 `AGH_HOME` 机制与数据物理隔离原理
在 Agnes Harness 官方底层架构中，环境变量 `AGH_HOME` 是决定系统一切数据持久化归属的唯一绝对根目录：
- **`data/`**：存放独立的 SQLite 数据库、事件总线与全部历史会话记录（`trace.jsonl`）；
- **`profiles/`**：存放每个环境专属的配置文件（`profile.yaml`）、模型提供商路由与默认账号；
- **`secrets/`**：以 0700/0600 严格权限独立加密保存各个环境的 API 密钥与安全凭据；
- **独立进程锁与 PID**：每个不同的 `AGH_HOME` 拥有独立的守护进程锁，**彻底消除了 SQLite 数据库锁冲突与会话串扰**。

### 2. 虚拟沙箱隔离环境 vs 实际宿主原生环境的对比与选择

系统内置三档开箱即用的预设运行环境，用户可在启动或安装时自由切换：

| 对比维度 | 独立物理科研环境 (Isolated, 默认推荐) | 虚拟沙箱隔离环境 (Virtual Sandbox) | 实际宿主原生环境 (Default Host) |
| :--- | :--- | :--- | :--- |
| **数据主目录 (`AGH_HOME`)** | `~/.agh-physics` | `~/.agh-sandbox` | `~/.agh`（系统全局默认） |
| **默认监听端口** | **4180** | **4182** | **4177** |
| **会话历史与数据库** | 100% 独立保存于物理科研专区 | 100% 独立保存于沙箱测试专区 | 接入全局主会话列表 |
| **Python 执行环境** | 优先调用系统 Python，便携包兜底 | **强制调用内置便携 Python 3.13 与预置 wheels** | 完全使用宿主机系统全局 Python |
| **宿主环境影响** | 零污染（不影响 4177 主环境） | **绝对零污染**（不修改宿主全局库，纯沙箱运算） | 共享宿主全局配置与模型凭据 |
| **典型适用场景** | 日常正式的物理科研推导与学术计算 | 安全测试、高危代码验算、脱网裸机运行 | 统一多任务集中管理 |

### 3. 多环境多端口同时多开实操流程
系统原生支持在同一台机器上**同时开启多个端口并行运行**。例如：
- **终端 1 运行物理科研实例**：
  ```powershell
  powershell -File scripts/start.ps1 -EnvMode isolated -Port 4180
  ```
  *访问地址：`http://127.0.0.1:4180`，查看和操作物理推导演算任务；*
- **终端 2 同时运行沙箱测试实例**：
  ```powershell
  powershell -File scripts/start.ps1 -EnvMode sandbox -Port 4182
  ```
  *访问地址：`http://127.0.0.1:4182`，以纯便携运行时进行独立沙箱测试；*
- **终端 3 运行已有系统默认实例**：
  ```powershell
  powershell -File scripts/start.ps1 -EnvMode default -Port 4177
  ```
  *访问地址：`http://127.0.0.1:4177`，处理通用工程任务。*

> **效果验证**：在浏览器中同时打开上述三个标签页，您会发现三个主页展现的是**完全不同、互不干扰的独立会话历史列表与模型配置**。关闭或重启其中任意一个实例，绝对不会波及其余实例的正常运行。

### 4. 构建防死锁与构建恢复机制（遵循官方 build-recovery 指南）
在 Windows 操作系统中，若直接在后台有进程运行的情况下尝试重新编译（`build:local`），极易触发文件被占用（`EPERM: operation not permitted`）的系统锁死报错。
为此，本项目严格依照官方《运行时构建目录中断后的检查》规范进行了工程加固：
1. **自动跳过无谓重编**：启动与安装脚本自动检测 `packages/cli/dist/local/agnes.mjs`。若核心编译包已完整存在，系统自动跳过编译，从源头杜绝并发文件锁冲突；
2. **安全重构控制**：若确需重新编译底座源码，请使用 `-Rebuild` 显式开关：
   ```powershell
   powershell -File scripts/setup.ps1 -Rebuild
   ```
   脚本会先优雅释放可能持有锁的旧守护进程，清理残留的临时构建锁目录（`local.build-lock`），再安全执行构建。

## 六、 常见问题与排查速查（FAQ）

### Q1: 启动时提示端口 4180 被占用怎么办？
启动脚本已内置端口检测与旧进程清理逻辑。如果端口依然冲突，您可以：
1. 在运行 `scripts/start.ps1` 时指定新端口，例如 `-Port 4188`；
2. 或者在终端执行命令停止已存在的守护进程：
   ```bash
   node packages/cli/dist/local/agnes.mjs daemon stop
   ```

### Q2: Windows 下执行 PowerShell 脚本提示“无法加载脚本，因为在此系统上禁止运行脚本”？
这是 Windows 默认的安全策略（Restricted ExecutionPolicy）。解决方式：
1. 直接双击根目录下的 `.bat` 批处理文件（内部已附带 `-ExecutionPolicy Bypass` 参数，不会触发系统拦截）；
2. 或者在管理员身份打开的 PowerShell 中执行一次允许本地脚本命令：
   ```powershell
   Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
   ```

### Q3: 离线生成的 HTML 学术报告能否在断网环境下正常查看？
**完全可以。** 报告采用单文件自包含设计，所有数学公式样式均已本地内联，矢量图表内嵌在 HTML 文件内部，彻底排除了外部 CDN 链接依赖，在完全断开网络的电脑上双击即可正常阅读与交互。
