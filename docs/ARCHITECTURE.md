# AI 物理科研工作站系统架构与技术设计文档

本文档介绍 AI 物理科研工作站（Physics Research Agent）的系统总体架构、核心组件分工、数据流转机制与安全隔离设计。

---

## 一、 系统总体架构与分层设计

本项目基于 Agnes Harness（AGH）智能体底座构建，采用**“核心底座通用、领域能力解耦、计算逻辑外部化、执行过程全留痕”**的分层架构设计：

│  • Web 工作台交互界面 (http://127.0.0.1:4180)                          │
│  • 单文件离线交互式科研报告 (内嵌三轨甘特图、正文蓝链热跳转与自由拉伸)      │

## 二、 核心子系统与功能模块

### 1. 宿主底座与安全隔离机制
- **命令受控执行**：大模型编写的所有外部 Python 脚本在运行前，均需通过系统弹出的审批卡片由人类用户确认授权，确保操作完全透明、在沙箱中受控执行；
- **环境隔离保障**：系统配置独立的用户数据主目录（`~/.agh-physics`）与独立的通信端口（默认 4180），避免与系统上已有的默认开发实例产生冲突；
- **端到端留痕**：每一次用户输入、模型推理、外部工具调用参数、控制台标准回显以及执行耗时，均由底座自动落盘记录于不可修改的 `trace.jsonl` 时序日志中。

### 2. 模块化技能解耦体系（1 个路由 + 9 个子技能）
为了防止将冗长的物理规则直接堆叠在单次系统提示词中引发大模型注意力分散，系统遵循平台零侵入扩展规范，在 `.agh/skills/` 建立了 10 个功能独立的技能模块：
1. `physics-agent-orchestrator`：中枢路由器，识别物理任务后分阶段引导模型按需加载对应技能；
2. `physics-agent-governance`：主控协议，统筹环境隔离、权限受阻即刻停顿与双路径成果交付；
3. `physics-state-check`：任务专属目录建立与状态机文件维护；
4. `physics-pipeline`：物理任务拆解、费米数量级先行估算与权威数据源决策；
5. `physics-defense-lines`：主方程量纲核验与极端退化极限检验规则；
6. `physics-auditability`：外部脚本运行资产归档与存证留痕；
7. `physics-report-charting`：科学图表规范与外置图例防遮挡准则；
8. `physics-report-writing`：科技研究报告八章行文与排版规范；
9. `physics-permission-shortfall`：网络受限自适应与便携运行时调度；
10. `physics-doc-parsing`：外部文献数据手册与图纸按需结构化解析。

### 3. 确定性物理检验与门禁工具链（`physics-agent/hooks/`）
- **符号量纲核验门（`dimensional_gate.py`）**：调用 SymPy 解析物理方程符号树，利用 Pint 物理单位库校验等式两端基本量纲指数向量，在数学形式化层面拦截量纲不匹配错误；
- **极端物理极限门禁（`boundary_gate.py`）**：读取 `boundary_spec.json`，自动化测试零引力极限、超远距离极限、质量无关性极限及参数单调性扫描，杜绝除零发散与非物理奇点；
- **报告出厂质量质检门（`report_quality_check.py`）**：在交付前执行 8 项程序化扫描，拦截元导语与底层调试代码，确保数学公式已通过内联代码离线渲染，图例无遮挡；
- **双栏交互排版引擎（`trace_visualizer.py`）**：将 Markdown 文本、矢量图表与执行时序融合为单文件 HTML 报告，提供正文蓝链与时序轨迹的毫秒级热跳转。

### 4. 权威基准数据层（`physics-agent/knowledge/reference_data/`）
内置来自公开发表渠道的标准科学数据集，脱网环境下模型可通过本地相对路径直接引用：
- `nist_codata2022_constants.txt`：CODATA 2022 基础物理常数权威表；
- `hydrogen_emission_lines.csv`：氢原子光谱特征线数据；
- `gistemp_global_anomaly_1880-2026.csv`：NASA GISS 全球地表变温观测序列；
- `nasa_exoplanets_mass_radius.csv`：NASA 系外行星质量-半径巡天观测数据；
- `sidc_sunspot_monthly_1749-2026.csv`：太阳黑子近300年月度连续观测数据。

## 三、 数据流转与执行生命周期

一个完整的物理分析任务在系统内部的数据流转生命周期如下：

1. **题干接入与路由引导**：用户输入物理命题，路由器技能识别物理特征，引导模型提炼核心目标并先做数量级粗估；
2. **状态初始化与数据获取**：系统创建任务专属子目录，建立 `problem_state.json`，并从 `reference_data/` 提取基准常量写入 `task_params.json`；
3. **推演建模与代码编写**：大模型推导演绎物理控制方程，在任务目录下现场生成独立的 Python 求解程序；
4. **外部计算与防线审核**：人类审批后调用本地 Python 解释器运行计算；计算完成后自动运行量纲门与边界门实施检验；若发现不合理异常，记录偏差并自动修改代码重新计算；
5. **图表绘制与双格式交付**：自动调用绘图脚本生成高精度矢量图，整合输出 `report.md` 源码，并编译为 100% 离线自包含的单文件交互式 HTML 报告。
