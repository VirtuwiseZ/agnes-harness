# 高空跳伞（Problem A: Space Diving）— 研究汇报

## Node 1 / 1.5 / 2a：任务规格、数据源路由、知识模板适配

**目标**：一个总质量 190 kg 的跳伞者（含航天服 + 降落伞）被火箭带到高空（可能高于大气层），从静止释放后自由下降回地表。求"能安全落地的最大释放高度"，安全标准取 5 g 持续过载上限（来自领域参数 JSON 中 5.0 g / 持续 5 s 的设计约束；另有 10 g / 0.1 s 的短时冲击上限作为次级校验）。

**数据源路由（Node 1.5）**：本题需要 T(z)/ρ(z) 结构数组作为 ODE 的输入系数（代码本身不感知数据来源，符合架构约定），以及一个**独立**的、可对模型 v-z / a-z 曲线做交叉验证的真实跳伞记录。

- 大气数据源：选定 **Level 0 本地 Python 包 `pymsis`（NRLMSIS-0 / 2.1，0–150 km，1 km 步长，共 151 点）**，因为该包已安装、可用、且一次调用即可覆盖本题需要的 0–150 km 全程，无需网络。做了一次跨源交叉检查：与另一个本地独立源（`ambiance`，标准大气型插值）在重叠的 0–80 km 区段做密度对比，最大相对差约 18%——这个差异本身是符合物理预期的（NRLMSIS 是包含热层结构的经验模型，`ambiance` 是更简单的标准大气插值），并作为后续敏感性分析的输入，而不是当作数据错误处理。可用性检查（真实拉取 0–150 km 全网格 + 39 km 单点抽查）通过：ρ(0 km)=1.169 kg/m³、ρ(100 km)≈5.9×10⁻⁷ kg/m³、T(150 km)≈637 K，均与大气层结构常识相符。
- 验证基准：选定 **Baumgartner 2012 年 39 km 太空跳**（领域参数 JSON 中的候选值，经本次确认作为基准）：峰值速度 467.7 m/s，峰值加速度 9.684 m/s²（≈0.99 g）。独立性判断：建模输入是"大气物理/经验模型"，验证基准是"真实跳伞事件的实测记录"，是**不同种类的数据**，不构成"用模型自己造的数来验证模型"的循环验证——独立性成立。

**知识模板适配（Node 2a）**：匹配到通用模板 `atmosphere-drag-ode.md`（拖曳主导的垂直下降 ODE 求解器）。该模板中"0.8 进入 / 1.2 退出跨音速带"的马赫数阈值直接沿用领域 JSON，未重新推导——按协议要求已在 `problem_state.json` 的 `knowledge_routing.routing_decision_audit` 里明确标注这是**沿用而非重新推导**的假设，后续边界门检查会检验其合理性。

## Node 2b：建模、数值求解、量纲门、边界门、验证

**控制方程**（对 u = v²/2 相对下降距离 x 的 ODE）：

du/dx = g_eff(z) − (ρ(z)·CD·A / (2m))·u

- 分四个飞行段（亚音速 / 跨音速 / 超音速 / 开伞后的"最终亚音速"稳态下降段）切换 CD 和 A，Mach 数按当地声速 a(z)=√(γRT(z)) 计算，声速基于当地温度 T(z) 插值。
- 数值方法：`scipy.integrate.solve_ivp`（RK45，rtol=1e-8），不是手写泰勒法——符合模板要求。
- 释放条件：从静止（v₀=0）在高度 z₀ 释放，纯垂直下降，无水平速度分量，火箭推力在释放后即消失。

**量纲门**：按规定应在数值求解前强制调用 `dimensional_gate.py`。实际尝试时发现该钩子脚本的维度别名表（DIM_ALIAS）缺少本题控制方程所需的 `area`（面积）和 `specific_energy`（比能，即 u 的真实维度）这两个别名——这是**工具本身的别名表缺口，不是物理建模错误**。已按协议要求在审计日志中如实记录"未能运行完成"，并补充了一份**手工量纲齐次性核查**（明确标注为补充性检查，不能替代未真正运行的量纲门脚本本身）：u 的维度是 L²T⁻²（比动能，J/kg），x 是 L，du/dx 是 LT⁻²；g 是 LT⁻²；拖曳项 (ρ·CD·A/(2m))·u 的维度是 (ML⁻³)(L²)/(M)·(L²T⁻²) = L⁻¹·L²T⁻² = LT⁻²，与 g 相同——两个加项维度一致，方程本身量纲齐次。

**数值实现过程中的一个真实缺陷（已在配额内修复，未触发退火回滚）**：第一版求解器的"事后加速度计算"使用了一个**重新仿真**的飞行段状态机，与 ODE 积分器内部实际走的飞行段切换序列并不完全一致（积分器在 RK45 的内部小步上可能触发了状态机切换，而事后采样点没捕捉到），导致 39 km 释放高度下峰值过载被高估约 3–4 倍（16.3 g 而非正确的 ~3.3 g），并且 95 km 与 100 km 之间出现了一个非物理的峰值过载"下凹"。修复方式：让 ODE 内部在每一步 `rhs` 调用时把当时的飞行段/CD/A 直接记入日志，事后加速度计算直接读取这份日志，保证事后曲线与积分器真实使用的力方程完全一致。修复后，峰值过载随释放高度单调递增（5/10/20/40/80/150 km 对应 1.07/1.40/1.68/3.27/7.88/15.37 g），非物理的"下凹"消失。这是典型的"下游代码缺陷"（而非物理假设错误），按配额规则记为 1 次重试（还剩 2 次）。

**边界门**（`boundary_gate.py`，6 个退化极限 + 1 组单调性扫描）：**全部通过**——z₀→0 时峰值过载→0；m→∞ 时峰值过载→1 g（接近纯重力，不爆炸）；m→0.19 kg（质量骤减）时峰值过载仍有限（~1 g，不爆炸）；CD→∞（极端拖曳）时峰值过载仍有限；CD→0（纯重力自由落体）时峰值过载=1.001 g（与"纯重力下 a 恒等于 g"这一解析极限吻合到 0.1% 以内，验证了求解器本身没有系统性偏差）；150 km 释放时结果有限（15.37 g）。单调性扫描（5/10/20/40/80/150 km 释放高度，峰值过载应随高度单调递增）：通过。

**与 Baumgartner 基准的验证对比**（39 km 释放，模型修正版）：
- 峰值速度：模型 538.9 m/s vs 实测 467.7 m/s，偏高约 15%——量级正确，偏差合理。
- 峰值过载：模型 3.27 g vs 实测 ~0.99 g，高约 3.3 倍。诊断：偏差集中在"降落伞段"的横截面积假设上——领域参数 JSON 给"开伞后最终亚音速段"的 A 只有 0.2 m²，这个面积比真实降落伞（一个 190 kg 系统对应的伞衣通常约 15–30 m²）小了大约 75–150 倍；用这么小的"伞"，模型自然要在更低的空域才追上"最终稳态"，从而产生比真实事件更集中的减速尖峰。这不是数值求解器的问题（CD→0 纯重力边界已验证到 0.1% 精度），而是**假设层（hypothesis layer）的参数局限**：即领域参数表描述的其实更接近"几乎没有真正的降落伞"的下降，而不是 Baumgartner 那种带真实大伞的下降。

## Node 3 结论（含为何该结论合理、以及什么情况下它会被推翻）

在上述参数表（m=190 kg；亚音速 CD=1.0 / A=0.18 m²；跨音速 CD=5.0 / A=0.18 m²；开伞后"最终亚音速" CD=1.2 / A=0.2 m²；马赫数阈值 0.8 进入 / 1.25 退出跨音速带；NRLMSIS 大气数据 0–150 km）下，**完整下降过程中峰值过载不超过约 5 g 的最大释放高度约为 55 km**（60 km 时首次突破 5 g，达到约 5.5 g）。

**这个结论为什么合理 / 需要怎样才会错**：

1. 该结论直接对应"给定参数表"下的数值结果，不依赖未经验证的手算极限；边界门（含 CD→0 纯重力 1 g 校验、m→∞ 校验）已经独立验证了求解器本身的数值可靠性。
2. 但**必须向使用者明确**：55 km 这个数字是**针对这套（伞面积明显偏小的）参数表**的结论，不能直接当成"配真实降落伞的人，从太空回来最安全能到多高"的通用答案。真实的大伞（15–30 m²）会比 0.2 m² 的"假伞"减速柔和得多，对应的最大安全高度应显著高于 55 km。Baumgartner 实测（39 km 释放，峰值过载 ~1 g）本身支持"参数表欠估伞面积会导致峰值过载被高估"这个诊断方向：模型对 39 km 释放的峰值速度（539 m/s）与实测（468 m/s）偏差只有 ~15%，说明大气数据和 ODE 主体没有大问题；峰值过载 3.3 倍的偏差几乎全部归因于伞面积假设。
3. 若要推翻 55 km 这个结论，最可能的途径是：把"最终亚音速段"的 A 换成一个真实量级的伞衣面积（例如 20 m²），重新跑一遍同样的扫描——这属于假设层的参数变更（不是数值方法变更），按协议应记录为一次新的假设层修订并重新走完整条边界门 + 验证流程，而不是在现有数值代码里悄悄把 0.2 改成 20。
