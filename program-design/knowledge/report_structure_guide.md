# 物理研究报告行文结构指南（从竞赛范文提炼，方法论层面，非答案）

本文档收纳从 `dev-notes/reference-solutions/` 目录下已知竞赛范文（2010-GM-B-210、
2020-GM-A-340、2023-GM-A-131）里提炼出来的**行文逻辑结构**，供 Node 3 撰写
报告时参考。提炼的是"这类报告应该怎么组织"的方法论，**不是**任何一道具体
题目的答案、公式或数值——具体数值和公式始终来自本题自己的 pipeline 运行
结果（Node 2b 的 `numerical_artifacts`），本文档只提供章节组织顺序。

## 从三份范文共同提炼出的标准章节顺序

| 顺序 | 章节 | 内容要求 | 对应 Node 3 增量写作时机 |
|---|---|---|---|
| 1 | 摘要 | 问题一句话概括 + 方法论一句话 + 关键结论（含数字和单位）。**先给答案，不先给过程**，跟正文顺序相反 | Node 2b 完成后（Node 3 最终整合时写） |
| 2 | 引言 / 背景 | 这个问题的物理背景是什么、为什么有意思、题目原始表述（原样引用，不改编） | Node 1 写完后追加 |
| 3 | 假设 | 逐条编号列出所有简化假设（"假设 1：……假设 2：……"），**不要**散落在正文里 | Node 1 完成后追加 |
| 4 | 建模（主推导） | 按物理阶段/子问题分段，每段开头先写"这一段要解决什么问题"，再写推导，最后写"本段结论" | Node 2a/2b 每完成一个机制段追加 |
| 5 | 验证 | 用独立数据源或独立方法（非同一模型自洽）验证模型预测，**在报告最终结果之前**完成。必须写明"验证数据来自哪里、跟模型预测差多少" | Node 2b 完成后追加 |
| 6 | 结果 | 最终答案，带单位、误差范围（若有）；若有参数扫描，把扫描结果表格/图放在这里 | Node 2b 完成后追加 |
| 7 | 优缺点 | 显式自我评价：这套方法做对了什么（strengths）、在哪里做了简化会引入什么误差（weaknesses），**不要**把 weaknesses 藏在脚注里 | Node 3 最终整合时写 |
| 8 | 讨论 / 未来方向 | 什么条件会改变结论（比如"若空气阻力不可忽略，答案会向哪个方向偏移"）；哪些假设若放宽会显著改变结果 | Node 3 最终整合时写 |

## 行文风格层面的三条约束（从范文的共性提炼，跟内容顺序无关）

1. **"结论先行"原则**：摘要和每个小节的开头都要先给"这个部分得出了什么"，
   再给"怎么推导的"。读者不应该需要读完整个推导段落才知道这段在说什么。
2. **"假设显式化"原则**：所有"我假设……"必须集中放在假设章节，正文里引用
   假设时用编号（"如假设 3 所述"），不在正文里临时引入新假设。
3. **"验证独立于建模"原则**：验证章节的数据源必须跟建模章节用的数据源
   不同（跟 `problem_state.json` 的 `independent_of` 字段一致），验证失败时
   要写明"失败在哪一步、差了多少、是否可接受"，不能只写"验证通过"。

## 边界说明

本文档**不是** §5（参考解答隔离规则）的豁免：它只提供"报告章节应该按什么
顺序组织"的方法论框架，不提供任何一道具体题目应该得出什么数值、什么公式。
Node 3 撰写报告时，具体填进上述各章节的内容，始终来自本题自己的 pipeline
运行结果（`numerical_artifacts`、`verification` 字段），不是来自
`dev-notes/reference-solutions/` 里任何一份范文的具体内容。
